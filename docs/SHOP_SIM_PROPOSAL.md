# 模拟经营玩法改造提案（SHOP_SIM_PROPOSAL）

> 状态：提案 v1（2026-09-30 起草）
> 参照样本：菜市场模拟器 / 守墓人 / 潜水员戴夫 / 旅者之栖 / 风之集市
> 落地原则：长在现有 sanguo-rpg 系统上，不另起炉灶；每阶段版本化 + 推 GitHub。

## 一、定位与核心循环

把现在的「盘下店铺 → 面板里买/卖/进货」升级为**双循环经营**：

```
白天：行军/探索（travel/field）→ 采特产/材料/情报/食谱
经营：城内铺（shop）→ 加工（酒坊/织坊）→ 上架定价 → 招待（客栈/酒肆）
结算：客流消费 + 行情波动 + 声望/贡赋（monthlyYield）
跨城：商队（货栈）低价城 → 高价城 套利
升级：声望点技艺树 → 解锁配方/自动化 → 扩产
```

经营产出（金银/名产/声望）反向补给势力线（贡赋/招降/军需），但经营失败不卡主线。

## 四、分阶段路线（P0–P4，每阶段一个版本号 + 推 GitHub）

- **P0 先有「经营感」**：自定价 + 顾客主动消费模拟 + 货架补货/断货 + 名产绑定探索采集。
- **P1 生产链 + 技艺树**：多级加工 + 技艺树解锁 + 雇工角色化（掌柜/匠人/伙计自动化）。
- **P2 双循环深化**：菜谱解锁 + 客栈经营 + 每日贵客事件 + 旅客委托闭环。
- **P3 跨城贸易**：行情波动 + 商队/货栈 + 互市/关市风险事件。
- **P4 抛光**：损耗/议价/装饰氛围/数值平衡 + 教程引导。

## 五、关键建议（红线）

1. 别一次做满 5 款；先做 P0 验证「经营感」成立再叠。
2. 全部复用已有 travel/field/npcai/facilities/broker/bank/地产（`house_deed`）。
3. 数值先粗后细，先用 `constants.js` 占位常量，跑通再配平。
4. 与主线解耦但联动：经营崩了不卡主线进度。
5. 顾客 AI 用事件驱动 + 跨日结算批量算，不每帧遍历（参考 `npcai.tickDay` 月概率式）。
6. UI 守 `docs/DESIGN_SYSTEM.md`：令牌 / `.btn` / `.tab` / `.pack-grid` 统一。

## 六、最小可玩验证（MVP）

盘下一家酒肆 → 探索采黍 → 酒坊酿成酒 → 上架自定价 → 次日客流来买、声望涨 → 用声望点技艺树解锁「批量酿造」。
