# 04 · 兵种扩展（A 类 · 形象差异化优先）

> 状态：**✅ 已落地（v20261111e，`aa8c95a`）**：4 兵种已注册 `troops.js`、`weakFire/trample/weakSiege` 判定、AI 出征权重池、纯墨立绘与 token 接入、玩家可招募，真机冒烟通过。下文为当时的设计决策与草拟数值，保留作设计基线；「接入流程 / 待落地」两节已执行完毕。
> 原则：只扩 **形象差异大、能无缝接入现有 6 阵位** 的 A 类兵种；不引入需大改引擎的机制（火伤/踩踏为轻量 flag，几行判定即可）。

---

## 拍板结论（2026-11-11）

1. **黄巾军按建议做**：黄巾力士 + 黄巾军（形象差异大、零新机制）。
2. **象兵复用骑兵机制**，但**立绘换大象+象奴**（区别于普通骑兵的马骑）。
3. **机制接受**：藤甲 `weakFire`、象兵 `trample` + `weakFire` + `weakSiege`（轻量改引擎）。
4. **数值先用草拟**（见下）。

最终扩展 **4 种**：藤甲兵、象兵、黄巾力士、黄巾军。太平道术兵（符兵/妖兵）、天公将军亲卫等留二期（需法术系统）。

## 接入流程（豆包出图后执行）

1. `troops.js` 注册 4 个新 key（atk/def/hp/spd/cost/upkeep/slot + 机制 flag）
2. 战斗引擎加 `weakFire` / `trample` 判定（`battlefield.js` / `combat.js` 几行）
3. AI 出征权重（`spawnTables` / 势力配置）加入新兵种
4. `tools/process_unit_art.py` 加 MAP/CROP，裁 256² WebP
5. CSS 三处登记（复用 `.bf-u-ico` / `.bf-ava-art` / `.bf-order-ico` 模式，加新 key）
6. bundle 两次 + `verify_versions.py` + 真机双视口
