**v20261030b 的分批调度器**（写在 `index.html` 内联脚本里，早于 bundle 执行，故各模块都能安全使用）：

- `window.__lfDefer(fn)` —— 模块把「非首屏必需」的预载登记进来
- `window.__lfStart()` —— 点「仗剑入世 / 拾卷续缘 / 存档槽」时触发：先注入字体，再把队列里的资源每隔 400ms 放一个（`requestIdleCallback` 兜底）
- `enterGame()` 里也有一次兜底调用，防止读档等路径漏触发
- 同时派发 `lf:game-started` 事件，供需要「开局信号」的模块监听

**回归实测**：首屏 1.95MB（bundle 1.20 / css 0.35 / 底图 0.10 / 图标 0.29），字体 0 请求、序章候选图 0 张；点「开始游戏」后 10 秒内分批加载 4.14MB（BGM 1.04 / 六张候选图 1.67 / 字体 0.84 / 捣药+赌坊 0.60）；进游戏、BGM 播放、`kitchen_pour` 分派均正常，0 个 pageerror。

## 一、待确认（可能是 bug，也可能是设计如此）

### ⚠️ #1 大世界点击「行脚货郎」没有反应

**现象**：逃出苦役营后抵达林径 `lindao`，NPC 列表里有 `👤行脚货郎`。

- 按钮**已解锁**（`class="nl-item"` 无 `.locked`，`pointer-events: auto`）
- `onclick` 存在，DOM click 执行成功、无异常抛出
- 但**完全没有反应**：无对话、无商店面板、无旁白变化、0 报错
- 连点 9 次均如此

**为什么没直接判定为 bug**：林径是**郊野**而非城市。可能设计上"行脚货郎在郊野不可交易，要进城才有"；也可能是 `talk()` 在这条路径走进了一个静默分支。两种情况都有可能，需先看清 `talk()` 走到了哪一分支再下结论。

**影响**：直接阻挡"买东西"这条核心路径。

**建议**：优先排查 —— 读 `engine.js` 的 `talk()` 与 `buildNpcActions`，看郊野 NPC 是否有交易入口。

## 二、确认为体验问题（非崩溃，但影响手感）

### #2 战斗结算与「破境」升级弹窗同时弹出

**现象**：战斗胜利后，`cs-confirm`（大胜结算）与 `#modal-card`（破境 LV 升级）并行出现，后者压在上层。

功能上没错（modal 本就该在最上层），但一次塞两个覆盖层，容易让玩家以为上一个没关掉。

**建议**：串行化 —— 关掉结算面板后再弹升级面板。

### #3 叙事/剧情队列过长且期间全局上锁

**现象**：从战斗胜利到可以自由操作，需要点掉约 **14 段**叙事（每段需点击跳过打字，实测 >20 秒）。
期间所有按钮被 `syncActionLock()` 加上 `.locked` + `pointer-events:none`。

**风险**：非常容易被误判为"卡死"（我第一轮排查时也以为是死锁）。

**建议**：给一个"点击整段快进"，而不是逐句点。

### #4 窄屏战斗菜单需横向滑动

**现象**：手机视口下 `#actions` 是 `overflow-x:auto` 横排，"撤退"要滑动才够得到；且首个按钮贴视口边缘易误触。

**建议**：至少让"普攻"和"撤退"始终可见/易点。

## 三、工程/流程层面

### #5 `prelink_gate.js` 因 jsdom 缺 canvas 而无法真正通过

**现象**：

```
jsdomError: Not implemented: HTMLCanvasElement.prototype.getContext
PRELINK GATE: FAIL  启动期错误 N 条
```

**性质**：环境限制（未安装 canvas npm 包），**不是代码回归**。
判断标准：只要出现 `bootedGame=true | getState()=ok` 且工厂列表齐全，引擎就是正常的。

**风险**：这条门禁长期红，久了会被无视，进而掩盖真实回归。

**建议**：给 CI 装 canvas 包，或显式豁免 `jsdomError` 中的环境类错误（只保留 TypeError/ReferenceError 为真错误）。

## 三、v20261030b 新增待确认

### #4 首屏字体 2.04MB 走两个境外 CDN（v20261030b：已移出首屏；是否彻底移除待定）

**现象**：首屏 6.25MB 中，**font/woff2 占 2.04MB（33%）**，来源是 `fonts.googleapis.com`（马善政 / 志莽行书法字）与 `cdn.jsdelivr.net`（霞鹜文楷）。实测本机 jsdelivr 那条直接 `ERR_CONNECTION_RESET`。

**影响**：国内网络下两个 CDN 大概率取不到 → 字体静默降级、水墨观感受损；取得到时要付 2MB 流量。这是**首屏最后一大块**，砍掉可让首屏降到 ~4.2MB。

**建议**（涉及视觉取舍，未擅自改）：① 正文霞鹜文楷改为系统字体栈（Win 雅黑 / macOS 苹方），只保留标题书法字；② 或把字体改自托管子集（下载字体到 `assets/fonts/`）。**需你拍板**。

### #5 同类「任务指路 → 物件不存在」风险（已做一次全量排查）

**背景**：上面 #G「灶边水缸」是这类问题的实例——提示写了、动作实现了，但没有按钮。

**已做排查**：脚本扫了 `objects.js` 暴露的全部动作函数，与整个 `shared/` 的调用点比对，确认 `kitchenPour` 是**唯一**孤儿动作（`CELL_INTERIORS` / `JOB_BOARD` 是数据对象非函数，属误报）；反向扫了 `city.js` 注册的动作 id，确认在 `engine.js` 的 switch 中无缺失。

**残留风险**：脚本只能查「动作函数有没有调用点」，查不了「NPC 对话 / 任务文本里提到的物件在对应房间是否真的生成」（那需要把每个房间的物件表与全部提示文本做语义比对）。后续若再遇到「提示有、点不到」，优先怀疑 `TUTORIAL_CITY_ACTS` / `CELL_INTERIORS` 的房间物件表漏配。
