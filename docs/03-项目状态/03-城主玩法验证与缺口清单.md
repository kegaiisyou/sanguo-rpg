## 0. 一句话结论（有立场）

**v20261112d 更新：P0 已落地，现在能从一座城逐城蚕食，直到打出结局面板。**
> 以下 §3/§4 保留为**实施前评估记录**，结论已被本轮推翻；实际落地与验证见 **§7**。

实施前的判断是：能摸到「据城 → 纳赋 → 养兵 → 再攻」的因果链，但撑不起一局完整的统一战役。

地基是好的：`conquerCity` 是归属唯一写入口，政令台/纳赋/委任/营造都按「此城是否归你」解锁，朔日会算钱，`checkUnify` 也真的会判天下一统。但玩家**只能肉身站到某座城里点「起兵略地」**，没有从地图上选目标出兵、没有命将远征、打完最后一城也没有胜利画面。所以现在验证到的是「城主日常」和「统一判定」，还验证不到「逐鹿天下的过程感」。

## 1. 验证手册（怎么点）

调试台入口：**进游戏后 → 设置 → 游戏 → 🛠 调试台**（标题页设置里不显示；`panels.js:443-445`）。本轮在面板底部新增「城主 · 统一验证」区块。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 下拉选一座城（默认已选一座非苦役营城） | 全图城池列表 |
| 2 | 点「**一键城主开局**」 | 自动脱籍、官职设「州牧」、银 +3000、部曲 500、军粮 1200、传送到该城**中枢格**、调试台自动收起 |
| 3 | 看场景动作 | 中枢格出现「**政令台**」（条件：立于中枢 + 城归己，`city.js:913`） |
| 4 | 政令台 → 征税/安民/内政命令、势力图、邦交 | 城主日常主路径 |
| 5 | 军营「募兵操练」→ 起兵略地（战棋三段攻城）；或山河志「迎战 / 攻掠」；或**势力图「举兵远征」→ 亲征 / 命将**（v20261112d） | 个人战与军事行动按 `05-战斗分流判定方案.md` 分流 |
| 6 | 调试台点「**推进 30 日**」 | 触发 30 次日结 + 朔日结算，看银两纳赋、群雄扩张、统一判定 |
| 7 | 调试台点「**查看统一进度**」 | 日志显示「治下 N / M 城，尚需 M−N 城」 |
| 8 | 调试台点「**全图归我 · 验证终局**」 | 全图易帜 + 立即 `checkUnify()`，出现「🏆 天下一统！」toast、大事记、主线目标「一统」可勾 |

另有两个轻命令：「授 城」只改归属与官职、不传送不给资源；「打开势力图」直接跳 `factionMap`。
「推进 30 日」若发现仍在教学期，会**自动脱籍以解冻时钟**（教学期 `clockFlowing()===false`，否则 `advanceMinutes` 直接 return、点了没反应）。

> 实现位置：`shared/core/dev.js` 的 `handleDev` / `renderDev`，依赖由 `shared/core/engine.js` 的 `LF.createDev({...})` 惰性包装注入（`conquerCity / forceRoom / cityGridSize / checkUnify / ensureArmy / advanceMinutes / openModal`）。刻意没用 `levyTroops` 给兵 —— 它会把 `rallyPoint` 设成驻守城，导致 `armyWithPlayer()` 为 false、起兵被「部曲不在身边」拦下。

## 3. 统一全图链路：断在哪

### P0 · 不补就没有「统一」体验

> **v20261112d 状态**：① 结局面板 ✅　② 命将远征 ⚠️ 部分（一次性后台判定，未做跨日行军/多军团调度）
> ③ 势力图选城出兵 ✅　④ AI 孤城护栏 **有立场地保留**（玩家不受此限，可亲手收官）
> ⑤ 夺城即时判定 ✅。详见 §7。
1. **没有胜利画面 / 结局分支**。`checkUnify` 命中只做四件事：置 `flags.unified`、写大事记、`log`、`toast('🏆 天下一统！')`；`openModal` 的 kind 分发表里没有 victory / ending / unify / gameover。`flags.unified` 的唯一消费方是主线目标 `unify` 打勾。`GAME_DESIGN_全量.md:511` 把「多周目与结局分支」列为待讨论。
2. **玩家势力被排除在逐鹿 AI 之外**。`warIsLordKey` 明确排除 `player`（`strategy.js:269`），攻方候选只由 NPC 诸侯生成 → 没有「命武将率军远征 / 从势力图点城出兵」的战略指令层。
3. **起兵只能打脚下那座城**。`openSiegePrep(state.room)` 与 `pendingSiegeCid=state.room` 都取当前房间（`engine.js`），山河志上点别人的城只能看详情，不能「选目标 → 发兵」。
4. **AI 自己打不出统一**。`warlordBattle` 与 `warlordDayTick` 默认拒攻都城、拒灭「有主势力最后一城」（`strategy.js:337-340, 391-394`），而 `checkUnify` 要求 `aliveReal===0`。结论：每家势力的最后一城**必须玩家亲手打掉**。
5. **判定要等朔日**。`checkUnify` 只由 `onMonthTick` 调（`strategy.js:438`），打光最后一城后可能还要等近 30 天。（本轮调试台的「全图归我」会立即调一次，仅用于验证，正式游玩没有。）

### P1 · 有骨架但体感弱

6. **没有「我方城池列表 / 按城委派太守」面板**。`ruledCities` 的 UI 消费只有计数、地图「据」章、主线目标；势力图只列城名，不提供按城下令。
7. **占领后的反馈薄**：无攻城战报归档、无「新得城池」面板、无治理目标或任务追踪。第零章里「反馈层 / 任务追踪 / 账本 / 战报」仍开放。
8. **时间推进摩擦**：调试台原本只有「时辰 +1」且不跨日、不触发月结；本轮补了「推进 30 日」，但正式游玩仍只能靠动作耗时慢慢推。
9. **远征后勤缺位**：起兵需部曲在身边 + 军粮 > 0（`war.js:311-321`）；`state.armies` 虽是多军团字典，却没有战略调度、补给线或多路协同。

### P2 · 内容量与边界

10. 第零章 C 档：80+ 张立绘无渲染入口（`combat-fx.js:buildPortrait()` 从未调用）、26 位武将头像未做；历史事件仅 7 条；婚姻 / 家族 / 子嗣全项目为零。
11. **大地图层刻意不碰城池归属**：`fieldarmy.js:3-4`、`settlement.js:3-4` 与 `01-进度与待办.md:175` 都写明不改 `cityOwner / ruledCities / cityWards`。所以「打垮行军部队 → 顺势取城」「平定聚落 → 纳入版图」目前不通，这是有意的边界铁律，不是 bug。
12. 门派 UI 口径冲突、非线性历史事件（玩家选择令事件不发生/延后）、影门 / 典籍争夺仍属规划未做。

## 8. 分期路线：从「三国志2 式」简化版走向最终版（v20261112e）

### 为什么先简化

完整战略层（跨日行军、多军团受命、补给线、每城驻军、玩家势力纳入逐鹿 AI）要同时改时间系统、军队模型、地图实体与归属引擎，牵动 `state.armies` 的数十处调用与 `time.js` 跨日 tick，是本项目风险最高的一片。而**三国志2 的范式只要求三样东西**：按月有限的命令书、一张我方城池列表、一次「选城 → 下指令 → 结算」的闭环。这三样全部能架在现有骨架上：

- 月序 `flags._monthKey` 已由 `time.js:60` 在朔日前写好；
- 城池归属唯一入口 `conquerCity`、开发度 `cityDevOf/setCityDev`、兵力上限 `LF.armyCapOf` 都现成；
- 用兵复用 v20261112d 的 `campaignTargets / attackCityFrom / commandCampaign`，**不新增任何归属写入路径**。

所以 v1 不是「砍功能的半成品」，而是一个**能独立玩通的回合制战略层**：按月经营、逐城推进、打出结局，全程不需要行军实体。

### v1（本轮已做）· 月度军令台

`openModal('grandStrategy')`「天下布武」：

- 每月命令书 `2 + floor(治下城数 / 2)`，夹 `[2, 8]`；惰性比对 `_monthKey` 复位，不强依赖月结一定被触发（调试跳月、读旧档都安全）。
- 治下城池逐城三条内政令：**开发**（银 200 → dev +6）、**募兵**（银 300 → 兵 +40，受 `LF.armyCapOf(title)` 上限）、**籴粮**（银 150 → 粮 +300），各耗 1 道军令。
- 进兵方向复用 420 公里邻接目标，「亲 征」走战棋三段攻城、「命 将」后台结算。
- 本月军令录（最近 12 条）、统一进度；势力图与调试台各留一个入口。
- **用兵暂不占军令** —— 这是 v1 有意的简化，v2 再统一预算。
- 面板复用 `.fm-my` / `.fm-row` / `.btn sm` 既有原语，未新增 CSS 类、未写死颜色与圆角（`DESIGN_SYSTEM.md`）。

### 已观察到的平衡问题（v2 必须先处理）

真机验证里，兵力 540 推进 30 日后降到 236（约 **-56%**），来自既有的日结军粮 / 逃兵 / 守城消耗。这会让「按月慢慢统一」在经营期被持续放血。v2 定数值前需先跑一遍 `tickArmyDay × 30` 的收支表，确认「一城纳赋能否养住一城驻军」，再定籴粮价、募兵数与兵损率。**本轮刻意不改既有平衡**，避免在引入新面板的同时动老经济。

#### 30 日收支表（v20261112g 真机实跑，口径：1 城 / 540 兵 / 1200 石 / 3000 两 / `rallyPoint=null`）

| 日 | 兵 | 军粮 | 银 | 士气 |
|---|---|---|---|---|
| 0 | 540 | 1200 | 3000 | 100 |
| 1 | 540 | 660 | 3000 | 100 |
| 3 | 540 | 0 | 3000 | 94 |
| 4 | 524 | 0 | 3000 | 88 |
| 10 | 436 | 0 | 3000 | 52 |
| 20 | 321 | 0 | 3000 | 94 |
| 30 | **236** | 0 | **3028** | 34 |

**根因（不是「守城消耗」，是军粮经济结构性死结）**：`army.js:45` 的 `upkeepOf` 按每兵 1 石/日计，540 兵即 540 石/日，1200 石**第 3 日见底**；此后 `army.js:341-346` 每日 `round(兵×0.03)` 逃兵复利，30 日正好腰斩。**一城月纳赋仅 +28 两**，而籴粮 150 两 = 300 石只够半天，补不上 16200 石/月的缺口（差约 290 倍）。

更卡人的是 `army.js:323` 的「驻守己方城就食补给」要求 `a.rallyPoint` 非空，而 `campaignCheck` 又要求 `rallyPoint===null` 才可出兵 —— **想出兵就不能补给，想补给就不能出兵**。下一批校准数值时须同时解这个门控（例如治下城数 > 0 即按「势力有根基」给随军部曲就食），本轮按「先做小的部分」未动任何既有经济参数。

#### v2 最小切片实施记录（v20261112g）

- ✅ **出兵纳入统一军令预算**：`attackCityFrom` / `commandCampaign` 共用 `spendWarCmd()`，扣 1 道 + 记军令录；军令耗尽即拦截，且先确认战前编成就绪再扣，不出现「扣了令没打成」。
- ✅ **逐城驻军 `flags.cityGarrison[cid]`**：`ensureGarrison()` 旧档一次性把现有部曲摊到治下城（避免开局无从发兵）；募兵令就地增驻；`campaignTargets` 记录 `origin`（距目标最近治下城）；`campaignCheck` 以该城驻军封顶出征兵力（不足 20 人拦截）；命将胜利后抽 35% 留驻新城、失利按 18% 折损，与全局兵损同步。
- 面板每城显示「驻军 N」、进兵方向显示「自 X 城发兵（驻军 N）」。
- **刻意未做**：逐城金/粮仓廪、独立城池列表页、跨日行军与多军团（v3）、玩家入逐鹿 AI（v4）。`state.army` 模型与战棋编成零改动。

#### v2 收尾（v20261112h）：军粮校准 + ③ 太守委任 + ④ 战报归档

- ✅ **军粮死结**：`army.js` 的 `upkeepOf` 乘 `UPKEEP_SCALE=0.02`（50 兵 1 石/日，原 1 兵 1 石/日）；「就食于民」门控由 `rallyPoint && own(...)` 放宽为「有任一治下城即可」，解开与 `campaignCheck` 的互斥。无城时仍不补给，断粮/逃兵压力保留。
- ✅ **③ 按城委任太守**：军令台每城行加太守下拉，复用 `Officers.appoint(id,'governor',cid)`（同城再任即解任）。`Officers.civilBonus(cid)` 已被 `monthlyYield` / `factionDomesticAI` 消费，故委任**有真实治绩收益**，不是纯摆设。
  - ★ 顺带修掉既有断链：`engine.js:579` 的 `Officers: Officers` 传的是晚定义变量（该处 L580-582 注释已记同款坑），实际为 `undefined`，`strategy.js` 内所有 `Officers.*` 一直走 fallback 1 —— 太守与守将治绩加成从未生效。新增 `Of()` 惰性从 `LF.Officers`（`engine.js:753` 挂载）取回，并替换本模块全部 8 处调用。
- ✅ **④ 战报归档**：`flags.warReports`（上限 20）记命将胜负与亲征发兵；`war.js:finishSiege` 结算回来后经 `window.pushWarReport` 把「发兵」原地升级为「城破/失利/鸣金」，同役不产生两条。军令台显示最近 8 役。
- **30 日收支表复验（同口径 1 城 / 540 兵 / 1200 石 / 3000 两）**：军粮按 10.8 石/日计，30 日约 -324 石；兵力不再出现每日 3% 逃兵复利。数值仍属「待调」，但「按月慢慢统一」不再被后勤持续放血。
- 仍未做：逐城金粮仓廪、独立城池列表页（v2 剩余）、v3/v4 全部内容。
