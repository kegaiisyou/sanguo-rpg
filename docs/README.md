## 给新人的 5 分钟上手

1. **这是个纯前端单机游戏**：无后端、无构建流水线，浏览器直接打开 `index.html` 即可运行。
2. **源码在 `shared/`，但浏览器实际加载 `shared/bundle.js`**（由 `tools/bundle.py` 把所有模块拼成单文件）。
   → **改了 `shared/*.js` 必须跑 bundle，否则线上不变**（这是本项目最大的坑，见 [05-恶性Bug与陷阱清单](01-工作说明/05-恶性Bug与陷阱清单.md)）。
3. **发布靠 GitHub Pages**：推到 `main` 分支即自动生效（有 CDN 延迟）。
4. **未 commit 前请三处版本号对齐**：`constants.js` / `tools/bundle.py` / `index.html` 的 `?v=`。
5. **动手前务必先读** [05-恶性Bug与陷阱清单](01-工作说明/05-恶性Bug与陷阱清单.md)，里面每条都是真实付出代价踩出来的，重犯成本极高。

## 仓库结构速览

```
index.html            单一入口（含少量内联 HTML/弹窗容器）
shared/
  bundle.js           ★浏览器实际加载的产物（勿手改）
  core/               引擎与各大系统模块（43 个）
  data/               静态数据（道具/名将/事件/图谱…）
  story/              剧情、房间、触发器（含夺营 coup）
  gen/                地点/房间生成器
  config/constants.js ★版本号唯一来源
  css/game.css        样式（不进 bundle，独立缓存）
tools/
  bundle.py           ★构建脚本（拼接+压缩+版本同步）
  bundle.manifest     ★合并顺序的唯一真相源
test/                 三道语法/交叉引用/prelink 门禁
```

## 一条最小改动流程（背下来）

```
改 shared/xxx.js
  → python tools/bundle.py（跑两次）
  → 版本号三处对齐（若跨版）
  → node --check shared/bundle.js
  → node test/syntax_check_all.js && node test/cross_reference_check.js
  → 浏览器实测
  → git add/commit + push
```

详见 [02-开发流程与版本迭代](01-工作说明/02-开发流程与版本迭代.md)。
