# 物品登记册

> v20260915g · 为什么要有这本册子：玩家在背包里看到"乱码"（一串英文 id），根子在**物品没登记就进了背包**。

## 一、乱码是怎么来的

1. `items.js` 的 `makeItem(defId)` 对**未登记**的 id 直接返回 `null`。
2. 若绕过它、直接往背包里塞自造对象（`packAdd({defId:..., name:...})`），背包里能显示名字，
   但**商店 / 寄售 / 详情**这些读 `LF.ITEMS[defId]` 的地方拿不到定义 → 掉回显示英文 id → 玩家眼中即"乱码"。
3. 同理，写了错别字的 id（dev 里的 `jinchuangyao`，正确是 `jinchuang`）会让按钮点了毫无反应。

**规矩**：凡能进背包的物，一律先在 `shared/data/items.js` 的 `DEFS` 登记，再在代码里引用 id。

### B 类 · 凭证与脏物（**不可交易**，货郎不收）

| 物品 | id | 为什么不能卖 |
|---|---|---|
| 劳字木片 | `lao_pai` | 营内饭票，出营即废；卖它等于自断口粮 |
| 戍卒腰牌 | `guard_tally` | 身份凭证，拿出来卖会惹祸上身 |
| 空白木牍 / 木牍路引 | `blank_pass` / `wooden_pass` | 伪造物，是"悬在头顶的刀"而非商品 |

**原则**：B 类不给价、不上架，只作剧情锁钥。若将来要让它能交易，须先给它一段"脱手"的剧情，而不是默默挂进商店。

## 四、新增物品时的三步

1. `items.js` → `DEFS` 加定义（`defId` / `name` / `icon` / `cat` / `price` / `desc` + `effect`）。
2. 若属 A 类：在 `shared/data/shops.js` 的货郎 `items` 里加 `{ id, buy, sell }`——**不在商店清单里就卖不掉**。
3. 代码里只引用 id（`packAdd('bumu',1)`），不要再塞自造对象。

## 五、产出要有第二个去处

一件物品只在一个地方用得上，那段内容就是悬空的：种出菜只能交差，交完农田就没了下文。
故农田（九畦）与伙房（大灶）刻意做成一条链：

```
田里播（菜籽 / 菽种） → 长成（野菜 / 菽豆） → 灶上煮（稀粥 / 豆粥） → 吃下肚（顶「灶上一口热饭」）
                                          → 交伙房鲁大（差役「开垦薄田」）
                                          → 拿去卖（货郎收）
```

判定一件新物品该不该加，看它是否在这条链上多出一个**分岔**；只是换个图标换个数值的，不立新物
（野菜入锅复用既有的「稀粥」，没有再造一个「菜羹」）。
