## 0. 三者如何咬合（一张图说清）

```
        ┌─────────────────────────────────────────────┐
        │            身份 / 势力 系统（骨架）           │
        │  state.identity.factionId / title / tokens   │
        │  政务中心(皇宫/州衙/城主府/政令台) → 政令面板 │
        │  权限矩阵：title × token → 可发政令           │
        └───────────┬───────────────────────┬─────────┘
        ┌───────────┴──┐              ┌──────┴──────────┐
        │  军队系统     │◀─虎符调兵─┘    │  历史名城      │
        │ state.army   │                │ cities.js+map │
        │ troops网格   │                │ 中央建筑随tier │
        │ 辎重背包     │─军粮/器械─▶政务 │ 许都=帝都特殊城│
        └──────────────┘                └───────────────┘
```

身份系统是**能力门禁（capability gating）**，不是职业锁死：平时你是游侠满世界跑；走进城主府、亮出太守令牌，这座城的政令台就对你开放；转身出城又是普通游侠。**角色不锁死，能力随「物 + 地」临时解锁**——这就是你要的"自由切换"。

军队系统从 `state.party`（现有随从）旁派生 `state.army`，不破坏现有队友战斗。
历史名城是内容填充，但"许都"这类特殊城天然成为身份系统里的「帝都/势力都」锚点。

## 1. 身份 / 势力系统

### 1.1 数据模型（新增字段，全部进 `shared/index.js:13 defaultSave`）

```js
// —— 身份/势力（v20260827 新增；normalize 自动补默认，无需手写迁移）——
factionId: null,          // 所属/统治势力 id；null = 无势力游侠
title: '游侠',            // 官职链：游侠→亭长→县令→太守→州牧→君主/皇帝
ruledCities: [],          // 玩家实际统治的城根房 id 列表（如 ['ji_guomen']）
tokens: [],               // 持有信物 defId 列表（身份令牌/虎符/尚方宝剑/圣旨/玉玺）
factions: {},             // 全局势力字典 { [fid]: { name,banner,ruler,cities:[],treasury:{gold,food},type:'npc'|'player' } }
```

- **官职链 `title`** 用有序数组 `LF.TITLES = ['游侠','亭长','县令','太守','州牧','君主']`，索引即等级。
- **信物 `tokens`** 是权限钥匙，存 `state.pack` 中（复用现有背包），引用其 `defId`。
- **`factions`** 既存 NPC 势力（董卓、袁绍…）也存玩家自建势力（玉玺称帝后生成 `type:'player'`）。

### 1.2 政务中心入口（复用现有基座，**零新建筑**）

现有 `genCityGrid`（index.html:3999-4007）已按 `tier` 放置中央建筑：
- `capital` → 皇宫 `🏯`（CELL_META.palace）
- 其余 → 衙门/城主府 `🏛`（CELL_META.gov，按 tier 显示「州衙/城主府」）

**改造点**：进入中央建筑（`BUILDINGS` 6833 区）时，若 `state.tokens` 含对应身份令牌，**追加「政令台」入口**（`openModal('edict')`）。
- 进城主府需「知县印/太守印」类令牌；进州衙需「州牧符」；进皇宫需「圣旨/玉玺」或身为君主。
- 无令牌者进入中央建筑只能闲逛，看不到政令台（能力门禁）。

| 征兵（本地） | ✗ | ✓ | ✓ | ✓ | ✓ | 无 |
| 征税（本地） | ✗ | ✓ | ✓ | ✓ | ✓ | 无 |
| 调兵（跨城） | ✗ | ✗ | △ | ✓ | ✓ | **虎符** |
| 修筑/升级 | ✗ | ✓ | ✓ | ✓ | ✓ | 无 |
| 任命下属 | ✗ | ✗ | ✓ | ✓ | ✓ | 无 |
| 宣战/易帜 | ✗ | ✗ | ✗ | ✓ | ✓ | **虎符** |
| 册封/称帝 | ✗ | ✗ | ✗ | ✗ | ✓ | **玉玺** |
| 先斩后奏 | ✗ | ✗ | △ | △ | ✓ | **尚方宝剑** |

> △ = 仅限本州/本城，跨域仍需令牌。

### 1.4 特殊物品（新增道具，cat 用 `'权柄'`）

| 物品 | defId | 权限含义 |
|---|---|---|
| 身份令牌 | `token_id` | 进入对应层级政务中心的凭证 |
| 虎符 | `hufu` | 调兵、宣战、起兵略地（联动军队系统）|

获取途径 RPG 化：任务赏赐、攻城缴获、奇遇、货郎（稀货）、朝廷册封。

### 1.5 "自由切换"落地

- 不引入"职业"字段，仅用 `title` 等级 + `tokens` 持有。
- 进政务中心 → 校验令牌 → 渲染可得政令（`renderEdictPanel` 按矩阵过滤）。
- 出城即恢复游侠体验；统治城仍可随时返回发令。
- 自建势力（`factions[fid].type='player'`）后，`ruledCities` 内所有城对其开放政令台。

## 2. 军队系统（把 dock 队伍扩成骑砍式）

### 2.1 数据模型

```js
// state.army（defaultSave 加默认；normalize 自动补）
army: {
  active: false,                       // 是否已成军（军营 recruit 后 true）
  troops: [],                          // 兵种格子：[{ type:'changqiang', count:50, xp:0, morale:100 }]
  logistics: {                         // 军队辎重背包（独立于个人 pack）
    items: [],                         // [{ defId, count }]，可装军粮/攻城器械/通用物资
    cap: 20                            // 容量 = base + 辎重兵*k + 民夫*m（见 2.3）
  },
  morale: 100,
  rallyPoint: null                     // 集结城根房 id
}
```

新建 **`shared/data/troops.js`** 定义 `LF.TROOPS`（骑砍式格子，可堆叠数量）：

```js

  daodun:    { id:'daodun',    name:'刀盾兵', icon:'🛡', atk:7, def:10,hp:28, spd:12, cost:1, slot:'步' },

  gongcheng: { id:'gongcheng', name:'攻城兵', icon:'🏰', atk:4, def:5, hp:22, spd:8,  cost:1, slot:'械', siege:true },

```

### 2.2 兵种格子（骑砍味）

- 每个兵种一个格子，`count` 可堆到数百（区别于随从 `state.party` 的"个体"）。
- `dock` 队伍面板（现有 party 系统 index.html:4657 起）改造为「军队视图」：**左半兵种网格**（图标+数量+经验条），**右半辎重背包**。

### 2.3 辎重背包（军队物资）

- 容量 `cap = 20 + Σ(辎重兵×8) + Σ(民夫×,5)`。
- 可装：**军粮**（随行军/驻扎每日消耗，独立于 `state.food` 个人粮）、**攻城器械**（起兵略地 siege 消耗）、**通用物资**。
- **与个人背包双向流通**：
  - `armyDeposit(defId,n)`：个人 pack → 军队辎重（受 cap 限制）。
  - `armyWithdraw(defId,n)`：军队辎重 → 个人 pack（玩家可拿点给自己用）。
  - 即你要的"投入 / 取用"两条都覆盖。

### 2.4 战斗接入（复用 CombatEngine 多单位架构）

`CombatEngine.init(playerStates[], enemyId)`（engine.js:42-59）已将 `playerStates` 数组映射为 `playerUnits`（engine.js:57）。**军队接入只需聚合**：

```js
// 构建玩家阵营：主角 + 随从 + 各兵种营级单位
function buildArmyPlayerUnits() {
  var units = [ playerStateAsUnit(state) ];              // 主角
  (state.party||[]).forEach(u => units.push(u));         // 现有随从（保留）
  (state.army.troops||[]).forEach(t => {
    var d = LF.TROOPS[t.type]; if(!d||!t.count) return;
    units.push({
      name: d.name+'营', idx: units.length,
      hp: d.hp*t.count, maxHp: d.hp*t.count,             // 聚合：数量×单位HP
      atk: d.atk*t.count, def: d.def*t.count, spd: d.spd,
      count: t.count, isTroop:true, artIds:['bingfa_base'],   // 兵种共用基础战法
      morale: t.morale||100
    });
  });
  return units;
}
```

- 战斗阵容变为「主角 + 周仓等随从 + 长枪营 + 弓弩营」对敌 —— 骑砍味就出来了。
- 战斗结算后按损失比例回扣 `troops[].count`，营级单位可「打光」但主角/随从不直接死（保留 RPG 单机体验）。

### 3.3 不做 / 二期（与现有州治所重复或体量小）

- ❌ 谯/小沛/平原/北海/南皮/庐江：被现有州治所吸收或体量小。

## 4. 存档迁移总策略（统一说明）

**核心利好**：`normalize()`（index.html:2750-2806）已对 `defaultSave()` 做「缺字段自动补默认」——

- 顶层字段：`if(s[k]===undefined) s[k]=def[k];` 直接补整个默认值。
- 嵌套对象（非数组、非 flags）：递归补子键，保留旧档已有子键。
- 数组字段（如 `party`）：顶层补全已覆盖；若未来新加数组字段，仿照 `normalize` 内 `if(!Array.isArray(...))` 显式补一行即可。

**结论**：三系统新增字段**全部在 `shared/index.js:13 defaultSave` 加默认值**，旧档载入即自动兼容，**无需手写迁移函数、无需改 `version`**。

⚠ **务必遵守**：`defaultSave.version='0.2.0'` 是存档 schema 版本，**切勿改动**。显示版本号仍按既有规则 bump（`constants.js` 的 `VERSION` + `index.html` 的 `?v=` 缓存参数）。

新增字段快速核对清单（实现时逐项确认）：
```
defaultSave 新增： factionId, title, ruledCities[], tokens[], factions{}, army{...}
normalize 新增： 若某字段是数组且需"旧档有则保留"，仿照 party 显式补（多数情况顶层循环已够）
```
