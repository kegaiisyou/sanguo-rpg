## 一、可立即修的具体 bug

### B1【必现】「定都」按钮点了传的是字面量 `+cid+`

`shared/core/panels.js:229`

```js
onclick="window.declareCapital(\'+cid+\')"
```

这段在**单引号** JS 字符串里，`\'` 只是转义的单引号，不产生拼接。实际渲染出的 HTML 是：

```html
<button onclick="window.declareCapital('+cid+')">
```

点击时传进去的是字符串 `"+cid+"` 而不是城池 id → `declareCapital` 必然失败。

**修法**：把单引号字符串改成拼接，或改用模板字符串：

```js
'<button class="btn sm" onclick="window.declareCapital(\'' + cid + '\')">'
```

全仓检索 `\'+` 这类误写**只有这一处**，不是批量问题。

### B2【必现】虎牢关等关隘的「返回关门」按了没反应

`shared/gen/rooms.js:103` 与 `:107`（瓮城 / 守营）

```js
actions:[{ id:'back', label:'返回关门', group:'行动', tip:'' }]
```

`handleAction` 里没有 `case 'back'`，点击静默。好在罗盘的「南 / 西」出口仍可回关门，所以玩家能绕过去——但按钮是死的。

**修法**：改为罗盘出口（删掉该动作，靠 `exits` 走），或在 handleAction 加 `case 'back'` 回上一房。

### B3【必现】「任务指路」最后一级静默失败

`shared/core/objectives.js:335-350`：本格点亮 → 罗盘直达 → NPC 询问 → **都没有就什么都不发生**。

玩家点了「前往」却毫无反馈，会以为游戏卡了。**修法**：补一行 `toast('此处无线索，且看日志或问路中人。')`。

### B4【必现】设施进度条口径与农历月错位

`shared/core/officers.js:719`：`(day % 30) / 30` 用的是**绝对天数取模**，而结算走农历月，两者会漂移 → 进度条偶尔"跳一下"。

**修法**：改为按"本月已过天数 / 本月总天数"计算，与 `facilitiesMonthlyYield` 同一口径。

### B5【必现】`cityStats` 写了没人读（玩家的经营不改变城市）

- 开垦/商业/探索写入 `flags.cityStats.{agri, com, defense}`（`officers.js:601`）
- 城市成长 `factionDomesticAI` 读的是**静态** `c.agri / c.commerce`（`strategy.js:475/499`）
- 全仓检索：`cityStats` 只有写入方，**无任何读取方**

实测连刷 12 次开垦，`agri` 涨到 24，但成长速度、纳赋、设施槽位一个都没变。
同类失联：`taxBonus()` / `orderBonus()` / `yieldBonus()`（`officers.js:155-171`）三个已导出的函数零调用；`OFFICE_EFFECT` 里 `pub`/`fin`/`eng` 三个 tag 无消费方（`buildings.js:68,69,72`）。

**修法**：让 `factionDomesticAI` 与 `monthlyYield` 读 `c.agri + cityStats.agri`，并把三个 bonus 接到纳赋/治安/成长上。

## 三、打开是空白的面板

### 3.1【必现·覆盖面最大】盘下 16/17 种商铺后面板是空的

`LF.TEMPLATES`（`shared/data/build.js`）**只有 1 条**（`yaofu` 药铺）。
盘下布庄、酒楼、铁匠、米行、钱庄……后，`shopTpl()` 返回 null → 客流 0、库存 0、营收 0，面板一片空白。

`shared/data/shops.js` 里 `SHOP_TYPES` 有 17 种、`SHOP_NAME_BANK` 分好了字号。

**修法**：给 17 种各补一条 `LF.TEMPLATES`（货品池 / 客流系数 / 周转天数）。这是"店铺经营"整条线的开关。

### 3.2【必现·条件触发】在不是自己的城打开政令台 → 空白

`shared/core/officers.js:745`：

```js
if (!cid || cityOwnerOf(cid) !== playerFaction()) return '';
```

玩家在别人地盘上点政令台，看到的是空面板，且**没有任何解释**。
同理 `renderCityMarket`、`renderEdictDelegates` 等也吃 cid 归属判断。

**修法**：返回空时给一句 `return '<p class="tip">你并非此城之主，无从发号施令。</p>';`

### 3.3【必现】城务志在无记录时空白

`shared/core/city.js:cityWardLog`（`wlog`）为空数组时，整个「城务志」页签没有内容也没有空态文案。

## 五、建议

### 5.1 先加两道"兜底"，让这类 bug 不再静默

这两条改动极小，但能一次性消灭"点了没反应"和"打开是空的"两个大类，强烈建议先做：

**① handleAction 加 default 兜底**（`engine.js:4098` 前）

```js
default:
  toast('此路未通（' + (a && a.id) + '）。');
  log('（调试）未分发的动作：' + (a && a.id), 'sys');
  break;
```

玩家立刻知道"这条路没做"，而不是以为卡死；开发者也能从日志里捞到漏网 id。

**② openModal 加空态兜底**

```js
if (!h || !String(h).trim()) {
  h = '<p class="tip">此处暂无可呈之事。</p>';
}
```

一行代码，所有空面板都有一句体面的解释。

### 5.2 加一个一致性校验脚本（防复发）

在 `test/` 下加一个静态检查：解析 `cityCellActs`/`cityActs`/`room.actions` 里的所有 `id:'xxx'`，与 `handleAction` 的 `case 'xxx'` 求差集，非空则 fail。

这个脚本能把上面第二节那一整张表变成 CI 里的一条红线——**以后新增动作忘了接线会立刻暴露**，而不是等玩家点到了才发现。同理可加：`onclick="window.xxx"` ↔ `window.xxx =` 的差集检查。

### 5.3 修复优先级建议

| 优先级 | 事项 | 理由 |
|---|---|---|
| P0 | 5.1 两道兜底 | 一行级改动，消灭两个大类 |
| P0 | B1 定都按钮 | 必现，且是战略层核心操作 |
| P0 | 3.1 补 17 条店铺模板 | 盘下店是空的，整条经营线不可用 |
| P1 | B5 接通 `cityStats` | 让"经营→城市变化"闭环（模拟经营的地基） |
| P1 | 2.1 官署坊五个页签 | 玩家高频点击点 |
| P1 | 5.2 校验脚本 | 防复发 |
| P2 | B2/B3/B4 | 单点小修 |
| P2 | 3.2/3.3 空态文案 | 体验细节 |
| P3 | 2.2~2.5 逐条核对 | 需先确认哪些真死、哪些另有路径 |

### 5.4 内容侧的两个"性价比最高"的补完

1. **店铺模板（3.1）**——`LF.TEMPLATES` 从 1 条补到 17 条，等于把"盘店—进货—定价—营收"整条玩法点亮，是现存数据最全、只差临门一脚的一块。
2. **官署坊六个页签（2.1）**——页签 UI 已经做好了，只差 `cityWards` 补条目 + handleAction 补分支，属于"骨架在、肉没长"的典型。
