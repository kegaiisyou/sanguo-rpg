## 五、技术约束与坑（必读）
- **`replace_in_file` 在本环境对中文整段不可靠**（报告成功但文件未改），且 `search_content` 结果会**滞后**（改完立刻搜仍显示旧内容，须 `read_file` 看真实字节）。改动一律用 Python 原生 IO 写回：
  `io.open(p,'w',encoding='utf-8',newline='')`，读取用 `io.open(p,encoding='utf-8')`；关键改动加 `assert s.count(old)==1` 校验。
- **Node 运行时**：系统无 `node` 命令，用
  `C:\Users\Administrator\.workbuddy\binaries\node\versions\22.22.2\node.exe --check <file>`。
- **版本号三处 + bundle 连跑两次**：`shared/config/constants.js`、`tools/bundle.py` 第 23 行 `VERSION`（硬编码，构建末尾会覆盖 constants）、`index.html` 的 `bundle.js?v`。`bundle.py` 只自动改 script 标签，**`game.css?v` 必须手动 bump**。改完**连跑两次** bundle.py。
- **bundle 校验**：terser 会 mangle 闭包内的函数名（`rummageOpen` 等在包里查不到），**验证只能 grep 特征字符串**（如「打开」「取物」「城旦之役」「水沟缺口」），不能 grep 标识符。
- **unicode 转义易写错**：校验脚本里手写 `\uXXXX` 极易出错（本轮就把「环**顾**四周」写成「环顺四周」、「壕**堑**」写成错码，导致误判）。**校验脚本一律直接写字面中文**，并用 `sys.stdout.reconfigure(encoding='utf-8')` 避免控制台乱码误读。
- **jsdom 冒烟两个坑**：① 内联 bundle 必须用**函数式 replacer**（`html.replace(re,()=>...)`），bundle 含大量 `$` 会被字符串 replacer 当特殊模式解析；② jsdom 无 canvas，须给 `HTMLCanvasElement.prototype.getContext` 返回 2D mock（返回 `null` 会在初始化期抛 `Cannot set properties of null (setting 'fillStyle')`，那是测试桩问题不是产品缺陷）；③ 需 `Image` 垫片让启动 loader 收尾，否则 `_waitPbg` 约 2.5s 后 `showTitle()` 清空 state，伪装成假 bug。
- **交互锁是 CSS 级**（`narr.js` 仅加 `locked` 类变灰），挡不住 JS 点击——对话悬挂（`askPending`）期间不要调用会顶掉 `tutAsk` 面板的动作，否则死锁。
- **对话分段不破坏串行队列**：分段会让 `logQueue` 条目变多，已确认 `lines` 数组逐句渲染（周听涛 6 句生效），解锁时序无需改动。
- **临时脚本**：根目录 `_*.py` / `_smoke.js` 为一次性补丁与校验脚本，本轮已清理（补丁均已落地并验证）。
