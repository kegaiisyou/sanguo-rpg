# 乱世烽火 · 生存建造向体检与工作计划

> 体检基线：v20260928d（shared 源码 30,338 行 / 43 core 模块 / 20 data 表）
> 规模实测：71 城 · 80 地点 · 151 物品 · 19 张蓝图 · 48 武学线 · 9 政令 · 4 设施 · 17 随机奇遇
> 本文只谈「作为一款生存建造游戏还缺什么」，不含战斗/剧情/战略层评估。

---

## 一、总体判断

**一句话**：这是一款「文字 RPG + RTK 式战略模拟」。生存与建造目前是**两个已通电但没接负载的子系统**——数值在跑（饥/渴/精力/建造/派遣），但缺少把它们变成「玩家每天要操心的事」的**压力源**与**反馈环**。

按品类标准打分：

| 维度 | 评分 | 说明 |
|---|---|---|
| 生存压力 | 4/10 | 饥渴精力有闭环，但死亡无代价、无伤势、无负重、无修理 → 没有张力 |
| 建造自由度 | 4/10 | 只能在既定 `empty` 格上建 4 种城市建筑，建成即终态 |
| 经营深度 | **6/10** | 设施派遣 + 政令层意外地扎实（本项目最强的一块，可直接复用） |
| 资源循环 | 3/10 | 战略资源仅粮/金/铁/器 4 种，无木/布/盐/药，无物价、无运输 |
| 内容量 | 7/10 | 71 城 151 物 80 地点，骨架够大，但**人均内容密度低**（建造物只有 19 种） |

**差的三块地基**：**基地（玩家没有一个"家"）**、**损耗（东西只坏不修）**、**季节（时间没有节律）**。
补上这三块，游戏才从"能玩"变成"值得活下去"。

## 三、核心缺口（按「为什么它现在不像生存建造游戏」排序）

1. **玩家没有家。** 买房只拿到一行日志，没有院子、没有家具、没有仓储、没有床铺加成。生存建造游戏的灵魂是"我的地盘"，现在玩家永远是流浪者。
2. **只有消耗，没有损耗管理。** 装备/工具耐久只减不修 → 长期游玩必然滑向"裸奔"，玩家所有积累作废。
3. **死亡没有代价。** 可无限读档续命 → 吃喝压力失去意义，生存层被架空。
4. **资源只有 4 种。** 木/布/盐/药不进战略层 → 生产链只有 1-2 层深，没有"产业链"的爽感。
5. **没有季节。** 农业、仓储、行军、保暖全部失去节律 → 时间只是计数器，不是压力源。
6. **野地资源只能散布采集，不能建成据点。** `RES_NODE_TYPES` 规划了 8 类资源节点（含 4 种矿脉），但 Phase 1 未实施；现在野地资源是 travel.js 随机散布的一次性采集点，玩家无法「占下来经营」。这是野外建造线最大的未兑现承诺（详见 8.9）。
7. **建筑建成即终态。** 无升级、无维护、不折旧 → 建造是一次性消费，不是长期投资。
8. **灾害不落在玩家身上。** 时疫只在内政层改治安数字，玩家永远不会失去一座谷仓。

## 五、优先级理由与排期建议

**为什么 P0 是这四件：**
- P0-1 是**现存断链 bug**（`RES_NODE_TYPES` 指空），成本最低、收益最直接——它同时是"野外建造"的入口，做完 P1 的整条资源线才有落点。
- P0-2「只坏不修」是**长期游玩的癌症**，任何长线内容都建立在"装备可维护"之上，必须早于内容扩张。
- P0-3 死亡无代价 = 生存层被架空，不修这个，后面加再多灾害都是摆设。
- P0-4「家」是生存建造的灵魂，也是 P2-6 宅院经营、P1-2 仓储扩容的容器，必须最先落地骨架。

**建议排期（按批次推进，每批一个版本号）：**

```
第 1-4 批   P0 止血与地基      → 游戏首次具备"家 + 可维护 + 有代价"三件套
第 5-11 批  P1 主循环          → 季节/资源/耐久/升级/负重，生存建造正式成型
第 12-19 批 P2 深度与威胁      → 伤病/灾害/商队，从"能活"到"活得有故事"
第 20+ 批   P3 长线           → 视玩家反馈择项
```

**一个贯穿性建议**：P1/P2 的所有产出型系统（宅院、仓储、商队、仆役），都**复用已成熟的派遣层**（`dispatchAssign` / `facilityOutput` / 月度结算），不要另起炉灶。玩家已经学会"派人去干活"这套语言，新增系统沿用它能极大降低学习成本，也让武将真正有事可做。

## 六、明确不建议现在做的

| 项 | 理由 |
|---|---|
| 实时建造/拖拽摆家具（图形化） | 与"文字即美术"的载体冲突，性价比极低 |
| 大型 UI 重做 | 当前 43 模块已稳定，UI 重构风险远大于收益 |
| 婚姻/家族/子嗣 | 全项目 0 命中，属独立大型系统，应在主循环成型后再议 |
| 继续拆 engine.js | 中枢（openModal/advanceTime/renderRoom/handleAction）已判定为高风险，收益低 |
| 增加更多城市 | 71 城已过剩（人均内容密度才是短板），应先补密度 |

---

## 七、一句话结论

**先把「家」和「修理」做出来（P0，4 批），再用季节把时间变成压力（P1），最后用灾害和伤病把损失变成故事（P2）。** 派遣层是这个项目最被低估的资产，新增的一切生产系统都应该挂在它上面，而不是另开一套。

### 8.1 结论：要补，但补的是三个「结构性空洞」，不是全面加量

### 8.8 🔧 工具等级：既有设计盘点（v20260915i，**不要重做**）

经核查，镐头已有一套完整且成熟的等级制实现，位于 `shared/data/items.js:414-461`：

```
LF.PICKS     6 级：粗石镐 lv0 → 精致石镐 lv1 → 青铜镐 lv2
                  → 粗铁镐 lv3 → 精致铁镐 lv4 → 百炼钢镐 lv5
LF.PICK_GATE 矿点门槛：{ gap:0, rock:0, big:2, copper:1, iron:3, jade:4, xuan:5 }
LF.MINE_SPOT 7 类矿点：岩缝/石堆/大石堆/古铜脉/铁砂堆/青玉脉/玄铁矿脉
```

**机制要点**（`shared/core/mine.js:19-42`）：
- 镐**不进背包**，是玩家自身的等级 `state.flags.pick`（0..5）
- **只升不降**：`upgradePick(lv)` 拒绝降级
- 每级 `hits{}` 表决定各矿点需敲几下，`-1` = 凿不动（镐刃弹开）
- 每级 `caveMax` 决定矿洞可下潜层数（2 → 9 层）
- **三条升级路径**：铁匠炉 `RECIPES.forge` 的 `pick:N` 配方 / 市集购得青铜镐 / 差役奖励

**为什么这套设计值得保留并推广**：
1. 背包只有 6 格（`BASE_PACK=6`），工具不占格是重大优势
2. 只升不降 → 无磨损 → 天然不需要修理系统支撑
3. 已跑通的晋升路径（锻造/购买/任务奖励）可直接复制到其他工具

**~~建议沿用等级制、不新增工具物品~~** —— **此建议已被推翻**：镐头六级的「等级制」虽成熟，但它让工具无法在行囊/装备栏作为道具存在，也与汉末材料升级逻辑脱节。见 8.10：已按用户决策全部改为**物品制**。

⚠️ **一处历史遗留需注意**：`items.js` 里另有物品 `pickaxe` 镐锄（maxDur=8，用于越狱「挖地道」线），与等级制 `flags.pick`（用于开矿）**是两套并存的「镐」**。属历史双轨，易混淆；建议在补工具时顺手把 `pickaxe` 明确为「地道专用」并改名（如 `dig_tool`），避免玩家与代码两侧认知分裂。

### 8.9 🔧 P0-1 修正：不是「修断链」，而是「兑现 Phase 1」

**先修了一个物品化带来的兼容缺口**：`chopTree` / `farmTill` 原用 `packFind('futou')` / `packFind('chutu')` 判断持械——工具一旦装备到 tool 槽就**不在行囊里，判成空手**。这是上一轮改造埋下的坑，本轮一并修复。

- `LF.heldTool(state, key)` —— 优先读「工具」装备槽；槽内无同系则取**行囊中该系最高阶**；返回 `{item, def, lv, equipped}`
