# 04 · 代码架构与模块约定

> 要新增/修改模块、跨模块调函数之前读本文。不遵守范式会产生"只在运行时才炸"的 ReferenceError。

## 二、IIFE 工厂范式（核心）

每个模块是：

```js
window.LF = {};
(function () {
  LF.createX = function (ctx) {
    // 依赖从 ctx 注入
    var getState = ctx.getState, log = ctx.log;

    function helper() { /* … */ }

    return { helper: helper };        // ← 步骤 2：暴露
  };
})();
```

`engine.js` 顶部用**别名块**接管：

```js
var X = City.X;                       // ← 步骤 3：别名
```

### ★ 三步必须齐全

**漏任一步 = 静默 ReferenceError，最早运行时才暴露。**
实战教训：曾把 helper 塞进工厂却没挂 `return` + 别名，导致 `renderRoom` 首帧崩溃、卡死进游戏。

**避险原则**：若某 helper **只有 `engine.js` 使用**，直接写成 engine 全局函数，别绕工厂闭包。

## 三、依赖注入的两条铁律

### 铁律 1：一切"会变"的绑定用 getter

引擎中 `Core.state` 在**读档/新游戏时被重新赋值**。

❌ 错误（捕获快照）：
```js
var state = ctx.getState();
function f(){ return state.day; }     // 读档后指向旧对象
```

✅ 正确（惰性取值）：
```js
var getState = ctx.getState;
function f(){ var st = getState(); return st.day; }
```

同理适用于 `settings`、`currentModalKind`、`cityBuildState` 等。
**primitive 类型尤其危险**（传值捕获快照，事后变化感知不到）。

### 铁律 2：向"早期工厂"注入"后赋值函数"必须包装

有些函数（如从拆分模块别名注入的 `renderMoveBar`）在引擎里**很晚才被赋值**，而工厂很早就执行了 —— 直接传引用会把 `undefined` 锁进闭包。

❌ 错误：
```js
var triggers = LF.createTriggers({ renderMoveBar: renderMoveBar, /* … */ });
```

✅ 正确：
```js
renderMoveBar: function(){ return renderMoveBar.apply(null, arguments); },
```

（与 `packAdd` / `startCombat` 同款范式。曾因漏包装导致线上崩溃 `TypeError: k is not a function`。）

## 四、几个容易踩的细节约定

### `_kind` 陷阱（`shared/gen/rooms.js`）

第 35 行 `if (o.kind) r._kind = o.kind;` —— **kind 被存成了 `_kind`**。

✅ 正确写法：`(room._kind || room.kind) === 'dungeon'`
❌ 错误写法：`room.kind === 'dungeon'`（永远 false，分支静默失效）

`spawns / loot / isBossRoom / floor / plot / battle / isBattlefield` 这些字段倒是正常保留。

### `__cell__:` 坐标协议（**冒号**分隔）

回城格子房间出口写 `__cell__:kuyilao:1:0`。
误写成逗号 `__cell__:kuyilao:1,0` → 解析出 `+'1,0'` = `NaN` → `TypeError`。
两处解析端（`exitDisplayName` 与 `move`）都按 `:` 拆。

### 房间物件的 action 只能调 window 暴露的函数

`story/rooms.js` 的 `buildRoomObjects()` 返回的 action fn，**点击时执行的作用域是 rooms.js 的闭包** —— 只能调用已挂在 `window` 上的引擎函数。

需要新增能力 → 先在引擎全局桥接块加：

```js
window.openRestModal = openRestModal;
```

然后 rooms.js 里用 `window.openRestModal(...)` 调用。

### 新模块必须登记 `tools/bundle.manifest`

否则不被打进 bundle，`LF.createXxx` 为 undefined → engine 崩。
顺序要排在依赖它的模块之前。

## 五、数据与 Nar\boldsymbol{内容}分层

- **数据**：`shared/data/*`（items / officers / cities / places / buildings / edicts…）
- **生成**：`shared/gen/*`（rooms / place rooms）
- **剧情与触发**：`shared/story/*`（含 `triggers_coup.js` 夺营链）

引擎通过 `checkTriggers({hook, ...})` 钩子触发剧情。
`window.checkTriggers` 已暴露（注释写明"供 playtest harness 触发 onEnter 夺营裁决"），
因此**可以用桥接直接触发剧情，不必靠 UI 走完整流程** —— 这是做自动化验收的重要入口。

同理可用：`window.advanceTime` / `window.advanceMinutes`。

## 六、UI 层关键约定

- 战斗时 `#app` 带 `in-combat` class，CSS 据此隐藏非战斗 UI。
  **新增底层浮层时，务必确认它在战斗态不会盖住 `#actions`**（历史上 `#dlg` 就因为这个导致战斗卡死，见 05 文档 #8）。
- 交互锁：`narr.js` 的 `syncActionLock()` 在 `interactBusy()` 时给按钮加 `.locked`（`pointer-events:none`）。
  所以"按钮点不动"要先看是不是叙事还没播完。
