# 06 · UI 交互与设计规范

> 改任何界面前先读本文。详细条目见 [../02-游戏设定/DESIGN_SYSTEM.md](../02-游戏设定/DESIGN_SYSTEM.md)（该文件为原始全文，保留未删）。

---

## 一、铁律（违反会被要求返工）

1. **颜色 / 圆角必须消费 `:root` 令牌**，禁止写死 `#xxx` / `rgba()` / `border-radius:Npx`。
2. **按钮统一用 `.btn` 及变体** `.btn-ghost` / `.btn-danger` / `.btn-sm`，禁止新造 `.xxx-btn` 类。
3. 面板切换用 `.tab`，子区块用 `.surface`。
4. **物品格子统一**：背包(pack)/战利品(cs)/仓库(storage)/给与(give)/工作台材料区
   共用 `.pack-grid` 与 `.cs-grid`（现已等价：桌面 5 列 / 手机≤560px 3 列 / gap 6px），
   单元格统一 `.packcell`（正方形 `aspect-ratio:1/1`）。
   **禁止为某一处格子另写 grid-template-columns / min-height / 图标字号**。
5. 详情统一 `.loot-info` 浮层，`.li-name` **不显示图标**（图标只在图鉴/无缩略图场景保留）。
6. 拖动鬼影要显示图标（`.pack-ghost` / `.loot-ghost`），禁止纯文字。

## 二、交互模型（务必沿用，改动需用户显式确认）

| 操作 | 行为 |
|---|---|
| **单击** | 选中 + 显示详情（含 装备/使用/卸下/修理/丢弃 按钮） |
| **双击** | 快捷动作 |
| **拖拽** | 交换位置 |

**破坏性操作（丢弃、放弃战利品等）必须二次确认。**

> 历史教训：`v20260928d` 曾把单击改成"直接装备"，属于改过头，`v20260929g` 已回退。
> 任何改动交互模型的提议都要先过一遍用户。

### 例外：装备在背包面板里单击即穿/卸

`pack.js` 的 `bindPackInteractions` 中，装备类**单击**直接穿/卸（`movePackItem` / `unequipToPack`）
并刷新高亮，跳过中间浮框；装备类**双击**才是查看详情。非装备仍走上面的标准模型。

## 三、店铺 / 建筑入口

**点击即进入**，直接打开对应模态面板（买卖 / 存取 / 制作 / 委任…），**不要先弹菜单**。

`.obj-menu` 浮动菜单方案暂缓，**未经讨论不要擅自落地**。

只有「交互物（松散物件 / 可交互设施）」需要 **2–4 个快捷动作**时才用 `.obj-menu`；复杂流程一律开模态面板。

---

## 四、按钮反馈

`game.css` 在锚点 `*{box-sizing:border-box;-webkit-tap-highlight-color:transparent;}` 之后有通用按压规则：

```css
button, .btn, .act, .li-act, ... :active { transform: scale(.95); }
```

特异性低于各处精细规则，因此不会覆盖它们，仅作兜底。新按钮自动继承。

## 五、容易被忽视但踩过坑的点

### 新增浮层前先想「层叠高度」

`#dlg`（对话框）是 `position:fixed; bottom:0; z-index:67`，高于绝大多数静态布局元素。
历史上它曾在战斗态没被隐藏，直接压住战斗指令按钮，导致**战斗完全卡死且无任何报错**。

新增任何底层浮层/固定定位元素时，务必确认：
- 战斗态（`#app.in-combat`）下它会不会挡住 `#actions`？
- 是否需要在 `in-combat` 规则里一并隐藏？

快速自查代码：

```js
document.elementsFromPoint(cx, cy)[0]   // 看最顶层到底是谁
```

### `interactBusy()` 会全局上锁

`narr.js` 的 `syncActionLock()` 在打字/等待选项/进度条运行时给按钮加 `.locked`（`pointer-events:none`）。
**"按钮点不动"先排查是不是这个**，而不是急着改代码 —— 排查时可先看
`btn.classList.contains('locked')` 与 `getComputedStyle(btn).pointerEvents`。

> 本轮实测：从战斗胜利到能自由操作，要点掉约 14 次叙事（>20 秒），期间全锁。
> 这段时间很容易被误判为"卡死"（我第一反应也以为是死锁）。
