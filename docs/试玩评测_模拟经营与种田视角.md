# 《乱世烽火》试玩评测 —— 一个模拟经营 / 种田老玩家的视角

**版本**：`20261020k`　**试玩方式**：纯逻辑层实机推演（加载真实数据层 + `Officers` 工厂，调用真实函数读真实数值）+ jsdom 载入真实 `index.html`+`bundle.js` 开局进涿县（0 报错）。

---

## 一句话总评

> **这是一款"骨架完整、血肉未接"的经营游戏。**
> 它有模拟经营最难做的部分——委派框架、月度结算、补给线、武将忠诚模型——都做出来了；
> 但它缺了模拟经营最容易让人上瘾的部分——**约束、取舍、反馈、以及"看着数字长大"的循环**。
> 目前的状态是：**有经营系统，没有经营玩法。**

---

## 一、先说好的：这几块是真下了功夫的

作为经营玩家，我最怕的是"面板一堆按钮，全是假的"。这款不是。

| 做得好的 | 具体表现 |
|---|---|
| **设施派遣公式完整** | `产出 = base × (1+主属性/100×0.85) × (1+特技) × (1+民夫/100) × (1+士卒/160)`，四个乘子分别对应"用人、用才、用民、用兵"，是有层次的设计 |
| **月度结算链条清晰** | `纳赋 → 群雄AI → 势力存亡 → 盟约清算 → 统一判定 → 事件 → 历史 → 存档`（`strategy.js:426`），顺序合理 |
| **补给线真的在跑** | 行军靠城寨补粮、断粮掉士气、缺 80% 逃兵、驻己方城就食于民（`army.js:296-350`），这是很多商业经营游戏都没做到的 |
| **武将忠诚有模型** | `target = 主公魅力 + (相性-75)×0.2 + 结义×8 - 宿敌×10`（`officers.js:133-146`），不是随机数 |
| **微观农场是真的** | `farm.js` 有完整的开垦→播种→生长→浇水→锄草→采收→留种循环，时辰制跨子夜不回绕，熟过头会荒死 |
| **钱庄有真机制** | 按城分账、异地汇兑按里程收汇水 `max(2%, min(20%, ⌈里/500⌉×5%))` |

**结论：地基是对的。** 问题全都出在"接线上"。

## 二、致命问题（P0）——这些不修，经营玩法不成立

### P0-1　内政命令零成本、零冷却、可无限刷 → 整个经济系统失效

**实测：**

```
=== 一天内连刷「开垦」12 次（每次 2 小时）===
第1次 → 粮 31      第4次 → 粮 124
第8次 → 粮 248     第12次 → 粮 372
12 次后 粮=372，无报错、无拦截、无衰减
```

`civilCommand`（`shared/core/officers.js:697-710`）的函数体只有：
`busyAct → applyEdictToState → advanceMinutes(120) → save → renderStatus → toast`

**没有精力扣减、没有资源投入、没有每日次数限制、没有失败率。**

后果链：

| 对比项 | 数值 |
|---|---|
| 亲行开垦 ×1（2 小时） | **31 粮** |
| 亲行开垦 ×12（一天） | **372 粮** |
| 派遣农庄满配（民夫80/士卒160/诸葛亮监理，**30 天**） | **128 粮** |

> **玩家花 1 天手动点 12 下 = 设施满配跑 3 个月的产出。**

这直接导致三个系统同时死亡：
1. **设施派遣**——精心设计的四乘子公式，被"狂点开垦"完全碾压，玩家没有任何理由去派将；
2. **自动化追求**——模拟经营的核心乐趣"从手动到自动化的升级感"，在这里是反向的：手动更强；
3. **时间资源**——时辰、精力、作息这套严谨系统，在经营侧等于不存在（唯一约束是吃饭喝水，而食物可从同一套命令刷）。

**这是我知道的这一类游戏里最典型的"数值没闭环"事故。** 修它优先级高于任何新内容。

---

### P0-2　两条最"经营味"的特技在数学上是死的

`facilityOutput` 取 `sumEff(ids, T.skill)`，而农庄/开垦/治水要 `farmMul`、商号/商业要 `tradeMul`；
但 `LF.OFFICER_SKILLS`（`shared/data/officers.js:10-41`）**只定义了 `devMul`**，没有任何技能带 `farmMul`/`tradeMul`。

**实测（同一农庄槽对比）：**

| 监理 | 属性 | 特技 | 产出 | skill 值 |
|---|---|---|---|---|
| 诸葛亮 | 政 92 | — | **128 粮/月** | 0 |
| 刘表 | 政 85 | **屯田** | **124 粮/月** | **0** ← 屯田加成完全未生效 |
| 曹操（商号） | 魅 — | **商才** | 26 银/月 | **0** ← 商才未生效 |

> 带"屯田"的刘表，产出**低于**没有屯田的诸葛亮。玩家如果看面板会以为特技有用，实际是纯装饰。
> 屯田、商才恰恰是三国经营题材最有辨识度的两条特技——它们空转，等于把题材优势浪费了。

---

### P0-3　玩家的经营努力，对城市数值零影响（死数值）

- 开垦/商业/探索写入 `flags.cityStats.{agri, com, defense}`（`officers.js:601`）
- 但城市成长公式 `factionDomesticAI`（`strategy.js:475/499`）读的是**静态** `c.agri / c.commerce`（来自 `cities.js`，永不改变）
- 全仓检索：`cityStats` **只有写入方，无任何读取方**

**实测：连刷 12 次开垦，`cityStats.agri` 涨到 24，但城市成长速度、纳赋金额、设施槽位——一个都没变。**

同理失联的还有三个已导出却无人调用的函数：`taxBonus()` / `orderBonus()` / `yieldBonus()`（`officers.js:155-171`），以及 `OFFICE_EFFECT` 里 `pub`/`fin`/`eng` 三个 tag 的乘子（`buildings.js:68,69,72`）。

> 玩家做的事不改变世界的状态——这是经营游戏最致命的一条。

---

### P0-4　经济只有收入、没有支出 → 没有压力，也就没有决策

**实测 12 个月挂机（治涿县，设施全部派将满员）：**

```
起始 300 两 → 12 个月后 1907 两（月均 +132）
粮 1003　铁 23　械 582
支出项：俸禄 0 · 维护费 0 · 民夫费 0 · 粮耗 0 · 行政开支 0
```

- **武将零俸禄**（全仓搜 `俸禄|薪俸|salary` 0 命中）——养 50 个名将和养 1 个成本一样
- **民夫/士卒是免费滑块**——`dispatchLabor` 只 clamp 上限，不扣钱不扣粮不占人口 → 最优解永远是拉满，不存在取舍
- **民众不吃饭**——粮草只有军队消耗，没有赈济压力
- **无建筑维护费、无房产税**

结果是**单调增长曲线**。经营游戏的张力全部来自"收入 - 支出 = 结余"这个等式，现在等式右边永远为正，玩家不需要做任何权衡。

## 四、缺失的模拟经营核心系统（P2）

按"对一个种田玩家的重要性"排序：

1. **物价 / 供需 / 区域价差** —— 最核心的缺失。`shops.js` 是静态买卖表，无城市/时间/库存修正。没有价差就没有贩运，没有贩运就没有商队，整个商业玩法无从谈起。
2. **季节 / 农时** —— `calendar.js` 有正月到腊月，但**只是名字**，农业完全不读月份。春种秋收是种田游戏的呼吸感来源。
3. **灾害（旱 / 涝 / 蝗 / 疫 / 霜）** —— 全仓只有 `plague` 一条月度事件。没有灾害，"治水"这条政令就是"城防+3"的伪装，粮仓、赈济、常平仓全是空谈。
4. **动态人口 / 民忠 / 流民** —— `c.pop` 是静态字段；没有民忠，没有民变，没有人口流失。经营游戏里"人"是最大的资源，现在人只是一个参数。
5. **税率调节滑块** —— 只有一次性"征税"按钮，固定公式 `(pop+commerce)/12+5`，治安 -4。轻徭薄赋 vs 横征暴敛的取舍完全不存在。
6. **城际物流 / 仓储** —— 资源是全局 `S().res`，无产地、无运输、仓储上限。多城经营因此没有"调运"这个玩法层。
7. **技术 / 农书 / 工巧树** —— 武学树只服务战斗，经营侧无科技。
8. **贸易 / 商队 / 关税** —— 外交已有（`diploPropose/diploSue`），但经济外交为零。

## 五、体验层：数字看不见，长线没目标

作为经营玩家，我最在意的其实是两件事——**我的钱怎么变的**和**我下一步该往哪走**。

现状：
- 月度结算只在日志里打一行 `〔营生〕麾下设施岁入：粮 128、银 26`。**没有账本，没有收支表，没有环比**，玩家无法复盘。
- 城市面板是一堆静态数字，**没有趋势箭头、没有历史曲线**。建设度从 62 涨到 63，玩家感觉不到。
- **没有经营向的长期目标/成就**。打下城池之后的驱动力全靠自觉。
- 设施进度条 `progress = (day % 30) / 30` 用绝对天数取模，与农历月边界可能错位，进度条会"跳"。

## 六、优化方向：分三阶段，建议按此顺序推进

### 阶段一 · 堵漏（投入小，收益最大，建议先做完再谈新内容）

| # | 动作 | 落点 |
|---|---|---|
| 1 | **给内政命令加约束**：加每日次数上限（如每城每令 1~2 次/日）、加精力/银两成本、把 base 砍到与设施同量级，让"亲行 = 亲自督导的爆发收益"而非"无限刷" | `officers.js:697` `civilCommand` |
| 2 | **修特技键错位**：给 `OFFICER_SKILLS` 补 `farmMul`/`tradeMul`（屯田/商才各 0.20），或让 `facilityOutput` 回退读 `devMul` | `data/officers.js:10-41` |
| 3 | **接通 cityStats**：让 `factionDomesticAI` 与 `monthlyYield` 读 `c.agri + cityStats.agri`，让开垦真的改变城市 | `strategy.js:475/499` |
| 4 | **补支出项**：加武将俸禄（按月 `Σ 品级×系数`，欠饷→忠诚暴跌）、加设施维护费、加民夫口粮（`labor × 1 粮/月`）、加建筑折旧 | 新增 `economy.js` 或挂 `strategy.js` |
| 5 | **民夫占人口**：`dispatchLabor` 上限改为 `min(laborCap, pop×系数)`，派兵去种地就没人打仗 | `officers.js:360-375` |
| 6 | **接上死函数**：`taxBonus` 接纳赋、`orderBonus` 接治安、`yieldBonus` 接成长；`OFFICE_EFFECT` 的 pub/fin/eng 找消费方 | `officers.js:155-171` |

> 这六条做完，游戏会**立刻**从"点一下涨一点"变成"需要盘算"。这是性价比最高的一次投入。

### 阶段二 · 让种田真正成立（这是题材最该有的一块）

1. **把农田从苦役营解放出来**：玩家自建的 `bp_farm` 农庄格可直接开垦；农田数量与城市 `agri` 挂钩，而不是固定九畦。
2. **作物从 2 种扩到 8~10 种**：粟、麦、稻、菽、麻、桑（养蚕→绢）、茶、果；各有生长周期、适种季节、耐旱/耐涝属性 → 这是"轮作"和"选种"决策的基础。
3. **加季节与农时**：春生夏长秋收冬藏，错季种植减产或绝收；农历已有，只需让 `plotStage()` 读月份。
4. **加灾害**：旱（减产）、涝（冲毁）、蝗（绝收）、霜（提前）。灾害要能被"治水/粮仓/常平仓"对冲 —— 这样治水政令才有意义。
5. **打通加工链**：菽→豆腐/豆酱、麦→面→饼/酒、稻→米→酒、麻→布→衣、桑→丝→绢。让"卖原料"和"卖成品"有 3~5 倍价差，产业链就成立了。
6. **农场可视化**：现在是纯文字列表。做一个小格子视图，每畦显示作物图标 + 生长阶段 + 缺水/长草标记，一眼扫过去——**这是种田游戏最核心的情绪价值**。
7. **加土壤肥力 / 轮作 / 休耕**：连续种同一作物降肥力，逼玩家轮作。

### 阶段三 · 经营深度（让长线有得玩）

1. **物价系统**（最高优先级）：每城每商品独立价格，`price = base × (1 + 供需失衡) × 城市修正 × 随机扰动`；丰收跌价、灾年涨价、战区暴涨。有了价差 →
2. **商队 / 贩运**：买低卖高，路上有劫掠风险，需要护卫。这一条能把"钱庄汇兑"和"郊野系统"全部盘活。
3. **人口与民忠**：`人口 = f(粮食盈余, 治安, 税率, 灾害)`；民忠低 → 逃亡 → 兵源与税收下降 → 恶性循环。让"人"成为要经营的对象。
4. **税率滑块**：0%~30% 连续可调，影响短期收入 vs 长期人口/民忠，这是经营游戏最经典的取舍。
5. **武将成长**：给 roster 加 `exp/level`，监理设施/执行命令积累经验，政务随经验成长 → 长期培养的爽感。
6. **科技/政略树**：屯田制、水利、冶铁、织造、漕运……用月度产出的富余资源去解锁。
7. **账本与图表**：月结弹一个收支明细（收入分项 / 支出分项 / 结余），城市面板加趋势箭头和 12 个月迷你曲线。
8. **经营向成就与目标**："仓廪实"（粮满万石）、"商通天下"（十城有商队）、"民安乐业"（某城民忠 90 持续一年）。

## 七、如果只做一件事

**先修 P0-1（内政命令无限刷）。**

原因：它是唯一一个"把其他所有系统全部架空"的 bug。只要它还在，设施派遣、武将委派、时间管理、资源规划——你后面做的任何经营内容，玩家都能用"狂点开垦"绕过。**它是这栋楼的地基裂缝。**

修法建议（最小改动）：

```js
// officers.js civilCommand 开头加
var _cd = S().flags.edictCd = S().flags.edictCd || {};
var _k = cid + '|' + cmdKey;
if ((_cd[_k] || 0) === S().day) { toast('此令今日已行，明日再议。'); return; }
_cd[_k] = S().day;                       // 每城每令每日一次
// 并加成本：exert(2) + 银两/粮草投入，把 base 砍到与设施月产出同量级
```

配合第 2、3、4 条一起做，**这一轮改动就能让整个经营层从"装饰"变成"玩法"**。
