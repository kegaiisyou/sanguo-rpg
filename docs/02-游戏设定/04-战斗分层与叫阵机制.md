# 战斗分层与叫阵机制 · 设计文档

> 版本：v20261112a 设计草案（未实现，待评审）
> 关联系统：`army.js` / `officers.js` / `combat.js`（RPG）/ `battlefield.js`（战棋）/ `war.js` / `settlement.js` / `strategicMap.js`
> 目标：消解「起兵略地打脚下城=政变」的违和感，统一「武侠（个人）vs 战略（军队）」的分裂，给玩家明确、可量化的战斗分层规则与主动「叫阵」机制。
> **评审结论（v20261112b）**：本草案 §3.4「按人数自动选 RPG 舞台」与 §3.1「成军线 500」经评审未采纳（见 `05-战斗分流判定方案.md` R1/R4）；
> §3.3 不可战拦截、§4 叫阵、§5 UI 文案予以保留，其中拦截已随 P0 落地、叫阵与文案留待二期。本草案不再作为实施依据。

---

## 1. 背景与要解决的问题

当前「起兵略地」以 `state.room` 作为攻击目标 `cid`，导致：

1. **政变感**：人站在哪座城，点按钮就打哪座城 —— 站己城=军变，站敌城=未出门先占城，都不合理。
2. **武侠 vs 战略分裂**：主角既是侠客（内功/招式/`learnedMartial`）又是主公（部曲/统率/`commandBonus`），玩家不清楚「我现在算带兵还是算侠客」。
3. **触发歧义**：大规模战争、小规模械斗、武装起义的触发逻辑混在同一个按钮里。

本文给出一套**可量化、对玩家可见**的明文规则，并把「战棋」定为底层通用舞台、「RPG 决斗」定为玩家可主动召唤的武将过场，从而统一三者。

---

## 2. 核心心法：两个可见数字决定一切

所有判定只依赖两个**永远显示在状态栏、遇敌时再显式宣告**的数字：

- **数字① 你的部曲数** `T = armyCount()`（即 `Σ troops.count`，见 `army.js` 的 `armyCount()`）
- **数字② 敌方是否有「首领/主将」** `enemy.hasCommander`（敌方数据里有无 named officer / boss 旗）

> 设计纪律：玩家永远不需要问「我到底在不在带兵」——因为他看到的是这两个数字，以及遇敌提示里明说的战斗性质。

## 3. 明文规则

### 3.1 规则 A —— 你是否「携带军队」（状态栏常驻）

| 你的 `T`（部曲总数） | 状态栏文案 | 含义 |
|---|---|---|
| `T = 0` | `行旅：孤身行侠` | 纯武侠层，无军队可用 |
| `0 < T < 成军线` | `行旅：携亲兵 T` | 小规模，可自保/剿匪，**不能发动战役** |
| `T ≥ 成军线 且 active` | `行旅：率军 T（成军）` | 可「起兵略地」发动战略级战役 |

- **成军线建议值**：`成军线 = 500`（汉末一「营」约 500–1000 人）。
- 当前开局 `defaultSave.armies.main.troops=[{count:1}]` 属「携亲兵」档（T=1）—— 所以开局能剿匪/劫掠（`settlement.js` 的 `attackPlace`），但**不能发动攻城战役**，正好消解「1 兵打城」的违和。想发动战役，先去军营募到 500。

### 3.2 规则 B —— 敌人是什么（遇敌提示）

| 敌方规模 `E` | 有首领？ | 战斗性质 | 玩家看到的遭遇提示 |
|---|---|---|---|
| `E < 50`（野兽/流寇小队） | 否 | **武侠个人战** | 「前方狼群，凭武艺剿除」 |
| `E < 500`（小股匪） | 是 | **斗将小冲突** | 「山贼头目率众拦路 —— 可斗将，亦可挥军围剿」 |
| `E ≥ 500` 或敌方=城池/军团 | 是/否 | **战略层（战棋）** | 「敌将X守Y城，列阵攻城」/「敌军团拦路，列阵接战」 |

- 阈值常量建议：`SKIRMISH_LINE = 50`、`STRATEGY_LINE = 500`（沿用 `RAID_KM=160` 的距离口径）。

### 3.3 决策表（A × B → 确定战斗层）

| 你方＼敌方 | 野兽/小匪（无首领） | 小股匪（有首领） | 敌军团/城（建制） |
|---|---|---|---|
| **孤身 (T=0)** | 武侠个人战 | 斗将（主角 solo vs 首领） | ⚠️ 不可战（提示「势单力薄，先募兵」） |
| **携亲兵 (0<T<500)** | 武侠个人战（亲兵助阵） | 斗将小冲突 | ⚠️ 不可战（未成军） |
| **成军 (T≥500)** | 武侠个人战（军队清杂兵） | 斗将+挥军 | 战棋（+ 敌将有则斗将） |

> **关键防困惑设计**：最右两格「不可战」直接拦截并 `toast` 提示，**绝不让你点进去打脚下的城**——这正是之前像政变的源头。

### 3.4 自动选舞台 vs 玩家主动叫阵

- **RPG 容量阈值**（回答「多少人用 RPG、超过多少用战棋」）：
  - `RPG_CAP_PER_SIDE = 6`（每方最多独立战斗个体；DQ 式 4 人队 + 缓冲）
  - `RPG_TOTAL_CAP = 12`（双方合计上限，超过自动用战棋）
- **自动档（系统按规模选舞台）**：
  - `双方合计个体 ≤ 12` → 直接 RPG（`combat.js`），不开战棋（如 主角+2随从 vs 头目+3喽啰）；
  - `超过 12` → 战棋（`battlefield.js`）。
- **玩家主动档（叫阵，任何战棋中都可）**：战棋中点「叫阵」→ 抽出双方将领做 RPG 决斗（永远 ≤ `RPG_CAP_PER_SIDE`，所以 RPG 永远装得下）。

> 统一模型：**战棋是通用战场（任何规模都能装：3 人也好、3000 人也罢），RPG 决斗是玩家在这块地上主动点出来的「武将过场」**。人少直接 RPG，人多先战棋再叫阵；敌拒叫阵就以寡敌众。主公本人始终在场上，既是侠客也是统帅。

## 4. 叫阵 / 斗将 规则

### 4.1 触发条件
- 仅当 `enemy.hasCommander === true` 时，战斗开场/战棋中提供「叫阵」选项。
- 野兽/杂兵（无首领）**绝不触发叫阵**（避免每战都单挑变套路）。

### 4.2 敌应战判定（让「拒绝→战棋弱势局」成为有原因的常态）
```
enemyAgreesDuel(enemy, playerTroops):
    if (!enemy.hasCommander) return false
    c = enemy.commander.courage           // 武将 courageous 属性（officers.js 可补）
    if (c >= DUEL_COURAGE_LINE) return true
    adv = enemyTroops / max(1, playerTroops)   // 敌方兵力优势比
    p = clamp(DUEL_BASE_P - adv * DUEL_ADV_PENALTY, 0, DUEL_BASE_P)
    return random() < p
```
- `DUEL_COURAGE_LINE`：武将「悍勇」阈值（如 70），达到必应战。
- `DUEL_BASE_P`：基础应战概率（如 0.6）。
- `DUEL_ADV_PENALTY`：优势越大越不愿单挑（如每倍优势 -0.15）。
- 例：solo 叫阵 3000 人敌军团 → 优势比极大 → `p≈0` → 敌拒绝、全军压上，玩家只能在战棋以寡敌众或突围撤退。

### 4.3 决斗规模
- 默认 1v1；玩家可带随行将领上场，上限 `RPG_CAP_PER_SIDE`（如 主角+关张=3 vs 敌将+2亲兵=3）。

### 4.4 结算（让「小兵旁观」有意义）
- 决斗**胜** → 敌对应营 `士气 -50%` 或直接 `溃散(rout)`（复用 `war.js` 既有 rout 概念）；
- 决斗**负 / 主角阵亡** → 己方该营 `动摇`，主角暴露有死伤风险；
- 不叫阵、直接挥军 → 走正常战棋/群战数值。

## 6. 流程伪码（落地参考）

```js
// shared/data/encounter.js（建议新建，纯函数 + 常量）
const RPG_CAP_PER_SIDE = 6;
const RPG_TOTAL_CAP   = 12;
const SKIRMISH_LINE   = 50;
const STRATEGY_LINE   = 500;
const ENLIST_LINE     = 500;     // 成军线

const ENCOUNTER_KIND = {
  WUXIA:        'wuxia',         // 武侠个人战
  SKIRMISH_DUEL:'skirmish_duel', // 斗将小冲突
  STRATEGY:     'strategy',      // 战棋
  NO_BATTLE:    'no_battle'      // 未成军打城，拦截
};

// 玩家出行状态
function travelStatus(state) {
  const T = armyCount();                 // army.js
  if (T === 0) return '孤身行侠';
  if (T < ENLIST_LINE) return '携亲兵 ' + T;
  return '率军 ' + T + '（成军）';
}

// 分类：返回战斗层 + 提示文案
function classifyEncounter(enemy, playerTroops) {
  const E = enemy.troops || 0;
  const hasCmd = !!enemy.hasCommander;
  if (E >= STRATEGY_LINE || enemy.isCity || enemy.isArmy) {
    if (playerTroops < ENLIST_LINE && !enemy.isBeast)
      return { kind: ENCOUNTER_KIND.NO_BATTLE, tip: '未成军，不可发动战役' };
    return { kind: ENCOUNTER_KIND.STRATEGY, tip: hasCmd ? '列阵接战，先斗将' : '列阵接战' };
  }
  if (hasCmd) return { kind: ENCOUNTER_KIND.SKIRMISH_DUEL, tip: '可斗将，亦可挥军' };
  return { kind: ENCOUNTER_KIND.WUXIA, tip: '凭武艺剿除' };
}

  return 'battlefield';
```

## 8. 防困惑设计纪律（务必遵守）

1. **触发规则全局唯一**：只用「规模 + 是否有名将」决定层，不凭心情分 A/B。
2. **UI 明确框定**：战棋盘=战略、个人卡=武侠、斗将过场=桥；玩家靠画面知所在层。
3. **主角始终在场**：主公本人即战棋里一个带兵单位（英杰传/骑马与砍杀范式），武侠层与战略层是他同一人的两面，不做硬切模式。
4. **两层互补不冗余**：武侠管个人恩怨/成长/快意，战略管地盘/人口/粮秣/大势；斗将让两者一起兑现。

## 9. 未决 / 待调项

- `ENLIST_LINE`/`SKIRMISH_LINE`/`STRATEGY_LINE`/`RPG_CAP_*` 的具体数值需结合现有兵力规模（如 `Settlement.compose` 的 3 营 5:3:2 权重）再校准。
- `officers.js` 是否补 `courage` 属性，或复用现有字段（如 `loyalty`/`brave` 别名）支撑应战判定。
- 自动 RPG（人少跳过战棋）是否默认开启，还是「永远先进战棋、由玩家决定叫阵」——后者更贴合本文「战棋是底层舞台」的设定，倾向采用后者。
- 决斗败北对主角的死伤惩罚曲线、以及「拒绝叫阵后以寡敌众」的撤退/突围出口需细化。
