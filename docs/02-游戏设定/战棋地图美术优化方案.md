# 战棋地图美术优化方案

> 版本：v20261109a · 2026-11-09
> 依据：豆包 2026-11-06 ~ 11-09 在战棋地图美术迭代中沉淀的 8 条工作记录（`Profile 4 / agent_mode / workspace / experience`）
> 范围：战棋沙盘 `.bf-grid` 地形格、地形贴图、格子线、单位可读性

## 一、定调（最终结论）

**「卡通／手绘元素的大小与布局 + 水墨的颜色与纸感」**，而不是纯水墨画，也不是纯色块。

11-08 的重要修正：**保持现有地形贴图的鲜艳度与清晰度不变，只在最上层叠一层极细的宣纸噪点纸纹**。
不要为了追求「水墨感」主动调淡颜色、换宣纸底色或加整体模糊 —— 实测会牺牲格子清晰度与单位可读性，用户明确反馈「没有上一个版本好看」。

## 二、已否决的方向（不要回头试）

| 方向 | 为什么不行 |
|---|---|
| 纯 AI 生成 tiles 直接拼接 | 每张纹理风格／明暗不一致，拼接有明显「补丁感」，细节不可控（树太多、山是远山视角） |
| 整幅水墨画「以画为棋盘」 | 没有格子感，不像战棋 |
| 纯代码色块绘制 | 太简单，没有水墨质感 |
| 统一底色 + 半透明叠加 | 方向接近，但装饰元素太小、不够明显 |
| 整体调淡／加晕染模糊 | 牺牲格子与单位可读性，用户否决 |

## 三、落地规范

1. 地形元素：手绘／卡通风格的小草、松树、山丘、水纹，尺寸适中，**必须留出放单位的空间**。
2. 底色：宣纸米黄，带细微纸纹；本轮用 SVG `feTurbulence` 灰度噪点（`opacity:.07`，128px 平铺）叠在 `.bf-grid` 背景层，不引入新图片资源。
3. 配色：保持现有地形贴图饱和度；淡灰绿／淡棕褐／淡灰蓝只作补充色，不覆盖主色。
4. 格子线：淡棕细线 `rgba(120,92,52,.20)` / 1px，不要硬黑线。
5. 单位可读性：复杂纹理（树林／山丘）上放单位会干扰识别，纹理密度要克制；高对比模式 `.bf-hc` 下纸纹关闭、地形回纯色。
6. 层级：纸纹放在 **grid 背景层**而非覆盖伪元素，保证不拦截格子点击、不盖住单位。

## 四、快速验证方法（不改代码、不重建 bundle）

1. 进战棋界面，在浏览器控制台用 IIFE 临时改 DOM：给 `.bf-grid` 设 `backgroundImage` 为候选图、`backgroundSize:cover`，遍历格子把 `backgroundColor` 设 `transparent`、边框设极淡半透明白，截图对比后再正式改代码。
   - 坑：控制台 JS 不能用裸 `return`，必须 IIFE 包裹；不把格子背景调透明会被色块盖住，只看到一块块色块；先确认容器尺寸与格子数再设背景。
2. 多块纹理拼接效果：优先本地 **PIL/Pillow** 方案 —— 下载纹理 → `Image.open` + `resize` 到 tile_size → `paste` 到 grid 画布 → 画格子线与单位圆点 → 输出预览 PNG。比浏览器注入 CSS grid 稳定（浏览器 session 容易 stale）。
   - 坑：AI 生成纹理的 prompt 里若写「瓦片／格子」，成图会自带网格线；下载图片时 curl 可能返回 2 字节，需 wget + UA。

## 五、AI 生成地形图的 prompt 约束

- 必须用**强否定句反复强调**排除无关元素：「绝对不能有人物、士兵、将军、骑兵、旗帜、军队、小兵，完全是空的地形，只有城墙、城门、房屋、树木、草地」。
- 只写「纯地形」「没有人物」不够，模型仍会自动加满屏小兵和旗帜；强化否定后仍可能残留少量元素，需代码擦除或重生成。
- 统一风格批量生成（草地／树林／山丘／河流／城墙），强调俯视图、无缝、低饱和古风、**无网格线**。

## 六、反馈协作约定

用户说「感觉不对／不太好」但说不清具体问题时：

- 不要继续盲目生成变体，也不要反复追问「颜色还是风格」；
- 直接给 3~5 个同类成熟游戏的实际截图作为**现成参照物**，让用户选最接近的一个，再按选定方向出方案。

- `shared/css/game.css`：`.bf-grid` 加 SVG 宣纸噪点（`opacity:.07`），`.bf-cell` 边框改淡棕细线，`.bf-hc` 高对比模式关闭纸纹。
- 地形贴图 `assets/battlefield/terrain_*.webp` 保持不变（不调淡、不模糊）。
