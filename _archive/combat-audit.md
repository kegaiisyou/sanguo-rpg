## 一、当前 Bug 与问题清单

### 🔴 P0 — 已确认的核心逻辑 Bug

**1. 自动战斗回放血条"反向"（历史：自动战斗功能已于 2026-07-31 移除）**
> 【状态：已修复】`playTurn` 内包裹 `log.push`，每条日志在出招当时即时打 `{eHp, pHp}` 快照；`startAutoBattle` / `handleCombatAction` 回放直接读快照正向渲染，手动与自动战斗血条均随出招顺序正向变化，无反向/跳变。下方现象描述对应早期 `runE -= dmg` 累加法（已被快照法取代）。
- 位置：`index.html` `startAutoBattle` 3056–3075 行
- 现象：
  - `st0 = G.CombatEngine.getStatus()` 取的是 `autoResolve` **算完后的终态**；
  - `runE = st0.enemy.hp`（胜方敌人终态 hp = 0）、`runP = st0.player.hp`（已扣完所有伤害）；
  - 回放时 `if(player_atk) runE -= dmg`、`if(enemy_atk) runP -= dmg`，而 `updateCardBars` 用 `Math.max(0,eHp)` 钳制（2861 行）。
  - 结果：**敌方血条开局即 0%**，整场无下降动画；**玩家血条从终态一路被减**到（终态−总伤害），回放末尾远低于真实值，最后被 `endCombat` 突然拉回真实 hp → **"血条暴跌后瞬回"的跳变**。
- 根因：`autoResolve` 是一次性算到终态，回放端却想"从满血正向扣血"，但拿到的初始值是终态。
- 建议修复（最干净）：让 `autoResolve` 在每条回放日志里附带该步执行后的 `{eHp, pHp}` 快照，回放时直接 `updateCardBars(e.eHp, e.pHp, ...)`，彻底消除累加误差。

**2. 手动模式"运招蓄力"预告与实际不一致（误导决策）**
- 位置：`engine.js` `playTurn` 第 2 步（beat>60 时 `_pickEnemyAction` 抢攻）与第 4 步（用 `enemyIntent` 预告招）；前端 `peekEnemyIntent` 在 `renderCombatRound` 锁定预告。
- 现象：玩家选"运招中"招式时，敌人实际会**先抢攻一次 + 再打预告招（两次）**，但 UI 只预告了主招，抢攻招未告知。
- 修复：运招中时在 UI 明确"蓄力→敌方抢攻"，或把抢攻招也纳入预告，或改为"运招中敌方伤害-50%"而非额外打一次。

### 🟡 P1 — 健壮性隐患（建议加固）

3. **`effectiveStats`（2776 行）装备字段缺失 → NaN 风险**：若装备对象缺 `atk/def/...` 字段，`es.atk` 可能为 `NaN`，导致全战斗数值异常。建议加字段默认值/校验。
4. **AudioContext 自动播放限制**：`SFX` 在 `setTimeout` 链中播放（自动战斗），浏览器要求首次用户手势后才 `resume`；若 `startCombat` 后 context 仍 `suspended`，音效静默。建议首点击显式 `resume()` 并提供静音开关（目前 `enabled` 标志存在但未接 UI）。
5. **`autoResolve` 不校验 `strategy`**：非法 strategy 走默认分支，日志可读性差，建议入参校验。
6. **`endCombat` 重复进入**：当前靠 `combatMode=null` 守卫（3080 行）基本够用，但"返回"按钮在 win/lose/draw/fled 各分支外统一添加，建议确认 defeated 态只留休整（已在 1648/1911 `if(state.defeated) return` 闭环）。

### ✅ 已修复
- `flashAnchor('hit hit-crit')` 触发 `InvalidCharacterError`（上轮提交 `cd9e0f3`，按空格拆分 token 逐个 `add`/`remove`）。

## 二、战斗系统功能完善规划

### A. 玩法深度
- **战意技策略化**：怒吼/死战目前是一次性 buff。改为"进攻型/防御型"区分、可叠层、怒气条可视化与解锁提示。
- **自动战斗策略可选**：`optimal` 之外增加 保守(保命)/激进(速杀)/仅普攻，让玩家按局势选。
- **敌人 AI 分化**：太平道偏 dot、华雄偏爆发、流民乱战——利用现有 `META.behavior` 差异。
- **连击/架势系统**：连续命中累积"架势值"，满则触发处决技（配镜头特写）。
- **战斗复盘面板**：胜利后展示总伤害、最高连击、暴击率、用时。

### B. 节奏与打击感
- 攻击**前摇/后摇**动画（敌我出手时间差），命中后停顿 ~150ms 强调打击。
- **关键一击特写**：暴击/斩杀触发慢动作 + 屏震 + 镜头推近。
- **连击数 HUD**、伤害数字分级（普通/暴击/格挡/闪避差异化字体与色彩）。

## 三、画面与体验优化（"体验差"的根因与对策）

### 根因诊断
当前表现为"体验差"，核心是**没有真正的美术与动作**：
- 角色立绘 = emoji（🥷👹⚔️，玩家 🧍），无姿态/动作；
- 场景 = CSS 渐变 + 墨滤镜（已有 `SCENE_THEME` 主题，但只是背景色）；
- 战斗卡 = 左右两张 emoji 卡 + 文字血条，信息密度低、缺乏"对战感"；
- 日志 = 纯文字流（虽已加图标/分类，但无回合分隔与事件高亮动画）；
- 受击/暴击/格挡虽有 CSS 动画（`.hit`/`.shake`/`.crit-burst` 已定义，512–532 行），但只是卡片抖动 + 一个小圆点，层次弱。

### 对策（按性价比排序）

**P0 — 立绘与场景（体验差的根因）**
1. **角色立绘方案**：用分层 SVG/CSS 绘制角色（头/身/武器可动），至少 4 姿态：待机/出招/受击/倒地；或引入 sprite 序列帧。emoji 仅作为占位降级。
2. **场景分层**：远/中/近景视差；按主题（雪地/营寨/祭坛）配廉价 SVG 插画 + 渐变氛围；保留 `SCENE_THEME` 映射。
3. **特效层升级**：受击粒子、暴击金色爆裂环、格挡蓝色护盾、闪避残影、斩击刀光（Canvas 或 CSS）。
4. **血条/怒气条美术化**：分段光泽进度条 + 危险脉冲。

**P1 — UI 游戏化**
5. 战斗卡改为"对战面板"：双方立绘对峙、中央回合分隔、日志改为带图标与分隔的"战斗播报"。
6. 字体/配色：标题用书法/衬线气质字体，主色 金+墨+朱，强化三国氛围。
7. 音频：BGM + 环境音（战场嘈杂/风雪）+ 招式差异化音效 + 胜负 jingles。

**P2 — 工程解耦**
8. **演出层与引擎解耦**：引擎输出"事件流"（已是日志数组），前端做独立"演出层"消费事件→动画，便于动画独立迭代、后续换皮。
9. **Skin/资源模块化**：立绘、场景、特效注册为 skin，便于扩展与主题切换。
