# 乱世烽火 · 开场体验复盘与「可复用叙事系统」方案

> 视角：以玩家身份走一遍开场 + 站到架构层面看"为什么只有开场能用这套引导"。
> 结论先行：开场引导的**交互原语（逐行叙事 / 选项 / 分层点亮 UI / 锁出口）本身就是好东西**，但它们被写死在 `ys_*` 房间和 `state.flags.onb` 里，无法复用到蓟城、渔阳、黑山寨等其他剧情。下面给出"把硬编码引导抽成数据驱动的 GUIDE 引擎"的方案。

> **📌 2026-07-31 实施进展（代码已落地、已推送 GitHub）**
> - **自动战斗已整体移除**（代码 + 文档）：`shared/combat/engine.js` 删 `autoResolve` 与玩家 AI `_pickPlayerAction`，`index.html` 删 `startAutoBattle` 与设置开关；半手动为唯一模式（节奏由「文字演出速度」档调节）。
> - **开场教学战已落地为脚本化演出**：在 `handleCombatAction` 顶部按 `tutCombatAct()` 分流，真实战斗卡面 + 剧情化出招，实现「剧情 / 引导 / 系统」合一——老乞丐无名掌法救场、主角被刀芒擦伤引出「行囊 / 疮药」教学，并把「攻击 → 防御 → 道具」三步引导串进同一场战斗。详见第八节。
> - **开场 NPC 列表改为数据驱动揭示**：`onbReveal('npc')` 从进局瞬间移除，改由 `intro_enter` 剧本在「点下方老乞丐」那一步 `reveal:'npc'`，避免开场文字未打完就提前交互引发 bug（开场叙述由 `suppressNarr` 抑制 `renderRoom` 自身，故 `intro_enter` 的 `narrate` 为唯一苏醒段，保留）。
> - 下文痛点 #5、第四节 #4、第六节 #4 已据此更新。

## 一、玩家视角走一遍开场（当前实际流程）

1. **捏脸**：填名字、选出身、分资质 → 点「踏入江湖」。
2. **村口（ys_entrance）**：屏幕先空，逐行打字播「苏醒」叙事 → 底部左侧浮现「老乞丐」。
3. 点老乞丐 → 弹出二选一（正经谢恩 / 懵圈问哪）。选完 → **底部「移动」罗盘点亮**，提示"往北"。
4. **北巷（ys_north）**：再点老乞丐 → 顶部「状态栏」点亮。又问"名姓"（随口报 / 闷声）。
5. **猎棚（ys_ne）**：触发脚本化教学战斗（乌桓游骑）。
6. 绕圈：东北→东南→南→西南→西→西北，最后 **山口逃脱（yanshan_shankou）** → 老乞丐留/走，`onb.done=true`，四向出口全开。

## 三、架构诊断：哪些是好的（已数据驱动），哪些锁死了

**✅ 已经做得好、可直接复用（请保持）：**
- `ROOMS` / `ROOM_OBJECTS`：房间与可见交互卡片（npc/building/feature/exit）已是声明式数据。
- `DIALOGUES.npcs`：NPC 名字/阵营/台词数据化，`talk(k)` 随机取台词。
- **`EVENTS` + `runEvent`/`findEvent`（2736/1731）：这是全项目最漂亮的"数据驱动选项结算"范式**——`choices[]` 带 `effect`/`moral`/`cost`，引擎统一结算。它才是应该被推广的模板。

**❌ 锁死在开场、无法复用（本次要重构的）：**
- `state.flags.onb` 整条链 + `applyOnboard`/`onbReveal`/`highlightOnb` 的"分层揭示"原语——**原语没问题，问题是只服务于 onb**。
- `tutorialBeggarTalk` 的 `if(state.room==='ys_entrance')…ys_north…` 硬编码对话树。
- `startTutorialBattle` 整段假战斗。
- `ONB_CHAIN` 出口锁。
- `talk(k)` 里 `if(k==='hanbo' && state.chivalry>=30)` 之类硬判断（2623）。

1. **名字贯穿叙事**：`tutorialBeggarTalk` 直接用 `state.name` 称呼玩家，删除重复的"问名姓"环节（或改成"老乞丐念出你捏脸的名号"）。

## 五、核心方案：数据驱动的「场景剧本 / 引导序列」引擎（GUIDE）

**目标**：把"开场引导"泛化为"任意房间可挂载的首访剧本"，让蓟城初到、黑山寨对峙、渔阳招募都能用同一套引擎。

### 5.1 新增数据层 `shared/story/guides.js`
把现有开场逐字翻译为数据；新增剧本只是再写一份数据。

```js
// shared/story/guides.js  （示意）
GUIDES.intro_yanshan = {
  trigger:{ room:'ys_entrance', firstVisit:true },
  objective:['与老乞丐交谈','随他往北撤','击退乌桓游骑','逃出燕山口'],
  reveal:['npc'],                       // 进入即点亮 NPC 列表
  steps:[
    { t:'narrate', lines:ROOMS.ys_entrance.desc },
    { t:'sys',     text:'点下方「老乞丐」与他交谈。' },
    { t:'npcTalk', npc:'beggar_old', branch:'entrance',
      asks:[
        { label:'多谢前辈救命之恩，晚辈听您吩咐。',
          set:{ personality:'serious', favor:1 }, reveal:['lower','loctab'],
          say:'少客套，保命要紧！点罗盘「北」。' },
        { label:'我……这是哪里？',
          set:{ personality:'transmigrator' }, reveal:['lower','loctab'],
          say:'甭管哪，保命要紧！点罗盘「北」。' }
      ]},
    { t:'moveGate', fwd:['北'], lockBack:true, hint:'乌桓骑兵追来，此刻不能回头！' },
    // ys_north / ys_ne / yanshan_shankou 的引导同理写成 step
  ],
  onComplete:{ flag:'onb.done', log:'〔老乞丐自此常驻燕山山口。〕' }
};
```

### 5.2 通用 Runner（取代 `tutorialBeggarTalk` / `onbEscape` 的硬逻辑）
```js
function runGuide(id, ctx){
  var g = GUIDES[id]; if(!g || alreadyDone(g)) return;
  // 依次解释 step：
  //  narrate → logScene；sys → log；reveal → onbReveal(layer)；
  //  npcTalk → tutAsk(asks)，选完执行 set + reveal + say；
  //  moveGate → 写临时 "fwd/lockBack" 到 state，renderMoveBar 直接读（取代 ONB_CHAIN）；
  //  event → runEvent；combat → startCombat(enemy,{tutorial:true})；
  //  setFlag → 置 state.flags；onComplete → 收尾。
}
```
- `renderRoom` 在 `room.guide` 存在且首访时调 `runGuide`。
- `talk(k)` 遇 `npc.script` 时走 `runGuide(npc.script)` 而非硬 if。
- `renderMoveBar` 读取 `state.moveGate`（取代 `ONB_CHAIN`），任何"被追击/护送"剧情都能锁回头路。

### 5.3 复用蓝图（同引擎，换数据即可）
| 场景 | 复用点 |
|------|--------|
| 蓟城初到（ji_guomen） | `firstVisit` 剧本：税吏盘查→点亮"行囊/武学"→给出"投军 or 游历"目标 |
| 黑山寨对峙（heishan_zhu） | `combat` step + `moveGate` 锁退路，Boss 前播台词 |
| 渔阳招募弧（duwei/liuyu） | `npcTalk` + `event` step，按阵营给任务 |
| 任何"被追/护送" | 只写一条 `moveGate` 数据，无需再抄 `ONB_CHAIN` |

### 一句话总结
开场引导的"逐行叙事 / 选项 / 分层点亮 / 锁出口"都是好原语，但被 `ys_*` + `state.flags.onb` 写死了。把它们抽成 `guides.js` 数据 + 一个 `runGuide` 解释器，开场只是第一条剧本；蓟城、黑山寨、渔阳立刻能复用，同时补齐"江湖志目标条 / NPC 任务钩子 / 真实战斗教学"三块缺失，整体从"只有开场会引导"升级为"任何场景都会讲故事"。

## 八、已落地范本：脚本化教学战（剧情 / 引导 / 系统合一）

> 这是「可复用叙事系统」的**第一份生产级实例**——它把开场的教学战斗从"假战斗 UI"改造成"真实战斗卡面 + 剧情化出招"，且零架构改动即可复用。后续蓟城、黑山寨的"教学型 / 剧情型战斗"可直接套用此 hook。

### 8.1 实现位置（代码层）
| 函数 | 文件 | 职责 |
|------|------|------|
| `tutCombatActive()` | `index.html` | 判定当前是否处于开场教学战（`state.flags.onb` + 战斗进行中） |
| `handleCombatAction()` | `index.html` | 战斗指令入口；顶部按 `tutCombatActive()` 分流：教学战 → `tutCombatAct()`，否则走真实 `playTurn` |
| `tutCombatAct(actionId)` | `index.html` | **剧情化出招**：每个玩家动作（攻击 / 防御）都先走脚本而非真实结算，但真实血条在卡面同步 |
| `tutThrowPack()` | `index.html` | 老乞丐甩出行囊 → 给金疮药 + 点亮「行囊」+ 解锁「道具」按钮（带防重复发放） |

### 8.2 核心机制
- **分流而非两套 UI**：教学战不重写血条/回合逻辑，而是复用 `renderCombatCard()` 真实卡面；`tutCombatAct` 只在"出招文案 + 关键数值（敌人受创、主角被刀芒擦伤）"上做剧情化覆盖，再 `renderCombatCard()` 同步血条。
- **剧情 / 引导 / 系统合一**：首击即播完整演出（你一拳打在空气 → 乌桓骑兵跃马挥刀 → 老乞丐无名掌法救场、你被刀芒擦伤 → 老乞丐甩出行囊），自然引出「行囊 / 金疮药」道具教学；「攻击 → 防御 → 道具」三步引导全部串入同一场战斗，不再因状态门控而跳过任一环。
- **乌桓骑兵增强**：`wuhuan_scout` 由 `hp170/atk20` 提升至 `hp240/atk38` 并加「跃马斩」（带流血），用以反衬老乞丐无名掌法之强，强化叙事张力。
- **与半手动的一致**：自动战斗已移除，教学战同样走玩家每回合指令，符合全局半手动基调。

### 8.3 复用蓝图（同 hook，换数据即可）
| 场景 | 复用点 |
|------|--------|
| 蓟城初到（税吏盘查战） | `tutCombatActive()` 改判 `state.flags.jicheng.tut`；`tutCombatAct` 换成"老兵替你挡刀、亮出「行囊 / 武学」"的文案 |
| 黑山寨对峙（Boss 前教学） | 同 hook，战败分支由老乞丐救场（`st.result='win'` 兜底），无需另写失败 UI |
| 任何"教学型战斗" | 只改分流 flag + 一份 `tutCombatAct` 文案，真实卡面 / 血条 / 道具解锁原语全部复用 |

### 8.4 与 GUIDE 引擎的关系
- 这是 **GUIDE 引擎在「战斗场景」内的最小可行实现（MVP）**：用 `if(tutCombatActive()) tutCombatAct()` 替代了原提案 `runGuide` 里的 `combat` step，但**不强制引入 `guides.js` 数据层**，先以函数 hook 验证"战斗内叙事可复用"这一假设。
- 完整 GUIDE 引擎（第五节 `guides.js` + `runGuide`）仍按原方案推进；届时 `tutCombatAct` 可平滑改写为 `runGuide('intro_yanshan_combat')` 的一个 step，逻辑不变、仅数据外提。
- 一句话：**先以函数 hook 跑通"可复用叙事"，再择机数据化**，避免为一场教学战提前背上 GUIDE 引擎的全部抽象成本。
